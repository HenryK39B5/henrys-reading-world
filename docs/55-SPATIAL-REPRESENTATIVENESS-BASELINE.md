日期：2026-09-26

## 问题与样本

名称附近有没有真实已复核成员支撑？全局 medoid 是否足以代替当前坐标中位数？

输入只用 `src/data/public-snapshot.json`：3,462 个固定公开点，56 个主题；1,432 个点有已复核标签，2,030 个未标注。不读取或发送 embedding，不重新取数，不移动点，不修改快照/词表/地形。

执行：

```powershell
node scripts/research/audit-spatial-representativeness.ts
npx vitest run tests/spatial-representativeness.test.ts
npm run typecheck
npm run lint
```

脚本输出 `.private/research/map/spatial-representativeness/baseline.json` 和 `baseline.md`，Git 忽略。JSON 记录输入文件 SHA256、地图版本、方法版本、全部主题和邻域成员 ID，支持逐条审阅；报告没有原文、向量、账号字段或凭证。再次执行覆盖同一基线报告；如果要比较改变了的数据/方法，应先单独归档该实验，不能拿不同输入 hash 的报告称同数据比较。

## 方法

- baseline：复算 X/Y 分别取中位数并验证等于公开 snapshot 的每个标签锚点。
- candidate：主题全部成员中的精确二维欧氏 medoid，最小化到所有成员的距离之和；不是平方距离。并列以稳定 ID 决定。
- 各锚点取全体公开点中最近的 15/30/60 个；逐尺度记录半径、同主题成员数、未标注数、已标注点内支持占比、相对全图已标注基数的 lift、支持成员书数/单书占比与邻居 ID。重叠点以稳定 ID 截断，需另做边界 ties 敏感性分析。

这些量只描述已审核支持，不是真实语义纯度。k 固定但半径随密度改变；当前 label display 的 10/18 上限、遮挡、出界、书名语境和高维一致性不在这个统计中。标签缺失也不按随机缺失假设处理。

## 实际观测

| 指标 | 当前中位数 | 全局 medoid |
| --- | --- | --- |
| 最近同主题成员距离的主题间中位值 | 179.21 | 必为 0，不作为质量收益 |
| 最近同主题成员距离 P90 / 最大 | 674.40 / 1,555.16 | 同上 |
| 最近 30 点内同主题成员数的主题间中位值 | 2 | 2 |
| 最近 30 点内同主题成员数 P90 / 最大 | 7 / 22 | 8 / 23 |

k=30 时，medoid 支持数比 baseline 高的主题 28 个、低的 8 个、相同的 20 个。medoid 邻域包含自身，至少一个支持点是算法必然结果；不能把这份比较解释成 28 个主题的语义位置得到证明。

结论：全局 medoid 可以消除“锚点完全不在真实成员上”的情况，但不能单凭这一点替换算法。当前证据不支持宣称获胜，也不构成显示/隐藏任何主题的 Gate。

## 接下来的反证与实验

1. 排除锚点自身、处理 k 边界 ties，并比较固定半径与固定 k；不能将稀疏处很大的半径误当局部支撑。
2. 预先选空心中位数、多簇、单书主导、较紧凑和低支持主题，先看原文再优化，另留主题/书籍验证。
3. 比较局部成员簇＋真实代表点；关注成员支撑、区域覆盖、书籍构成和各尺度稳定性，不优先填满文字。
4. 高维 embedding 核查及主题条件化投影另起实验；当前位置统计无法证明高维语义一致性。
5. 同图/同标签画 1440/390/320px 配对图，检验真实文字落点、避让后的位移及点击邻域；统计锚点通过不等于最终屏幕标签有代表性。
