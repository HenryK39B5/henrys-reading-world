## DeepSeek 的施工顺序

1. **V2-A：** schema 2、稳定 ID map、书籍 dossier、书籍主题分配、全量 local-only 快照。
2. **V2-B：** 先公平选书再选句的 Discovery Engine，增加 all/theme 持久 stage scope。
3. **V2-C：** 主题舞台与信息架构迁移；主题点击进入舞台，年份只属于书籍。
4. **V2-D：** 130 本与全量单书划线的分批浏览、性能和可达性。
5. **V2-E：** 稳定深链、复制、分享卡、错误态、200% 缩放和最终打磨。

每片单独实现、测试、浏览器验证、更新 `docs/08` 并做小步本地 commit。不要一次重写全项目。

## 实现边界

- 只使用已有真实数据，不造句、书、作者、年份、标签覆盖或统计。
- 主题属于 Book；Highlight 不再逐句打标签。UI 必须说“主题书架中的书”，不能说“这句话属于某主题”。
- 不引入 embedding、向量库、运行时模型、逐句 Agent 分类、推荐学习或 analytics。
- 随机优化公平、防重复与可用性，不使用质量分、Opening/Surprise 或人设叙事。
- 全部划线都要有路径可达，但不能在首页或 DOM 中同时铺开数千条。
- 继续保护 `.private`、API key、原始账号/bookmark 字段；不部署、不 push。
- 视觉方向已经通过：保留文字中心、真实封面和小面积封面取色，不继续加首屏图像与颜色。

## 回到高推理模型 / 用户的条件

只在以下情况暂停并升级：

1. 真实数据无法支持 8～15 个宽主题，或书籍分类出现无法用“书架语义”解释的重大冲突；
2. schema 2 必须丢弃现有稳定 ID；
3. all/theme/book scope 在产品行为上出现 docs/10/11 未覆盖的冲突；
4. 拟增加搜索、embedding、社交、部署或其他非目标能力；
5. V2-C 有真实页面截图后，需要再次进行视觉/产品 review。

普通代码结构、测试、分页数量和局部样式不需要逐项询问。
