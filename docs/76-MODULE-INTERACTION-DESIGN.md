# 76 — 各模块功能与交互设计：让一句话通向整个阅读世界

日期：2026-09-27。状态：**功能/交互设计提案，优先于独立“体验审计”；尚未实现或通过Henry的逐项产品Gate。** Henry认可`docs/74`整体分工，特别指出下一阶段最重要的是**各模块的功能设计、交互体验**，其余跨页样板/产品艺术Gate方向可继续。计划见`docs/75`。本文件不替代已上线产品的路由和数据契约；只为隔离本机联动样板定义要比较的动作，不能据此删现有模块、改公开快照或部署。

## 一个访客动作语法

- **读**：无论来源，每次只让一条有出处的完整真实划线成为阅读焦点；读者能说出书名、知道是否有经审核的逐句主题，而不把未审核当作没有主题。
- **继续**：按钮必须回答“下一句从哪里来”。首页跨书公平偶遇，书房只在这本书，小径只沿当前已审核Topic Tag。地图没有自动“下一句”：读者自己点位置/书/主题。
- **转换**：句子ID不因打开书/小径/地图自动换掉；当前原文若属于所选书/标签，就以它为进入锚点，在显式按一次继续后才离开。无标签时不提供伪主题入口，仍可读、开书、看地图。
- **返回**：回到同一句、原地图视框/原目录位置/原小径进度；浏览器Back、刷新与从分享深链进入应有可理解的结果。跨模块位置的保存方式可不同，不强行让所有抽句器共享一条状态机。

现行`src/app/Nav.tsx`已经有「随便看看／主题书架／主题小径／世界地图／所有书／关于」**六项一级入口**。这次不靠增菜单解决问题：先设计点击后发生什么。下列“目标动作”与已发布代码须分开：目前地图`MapRoom`已有总览/区域/书籍点亮/真句详情与`?h=`，首页/主题书架`StageRoom`都有随机换句，而从首页原句进入书房或小径**不保证以同句作为其第一句**（`useBookWalks`/`usePathWalks`分别独立初始化）。这些是针对功能设计的定点代码核对，不是长篇体验审计或改版已完成的证据。

## 1. 主入口：随便一句

**访客要做**：先读一条真划线，愿意就再遇见另一条；想深入才展开出处或去书/主题/地图。页面第一眼是正文和可见书名，“再来一句”唯一强主动作；分享在次级，不同时摆自动续读/选路两种阅读模式。原有按书公平、去重、长句原文、深链分享规则保留，不能改成原空间前16模型接句。

**交互次序**：点书名→原位展开封面、作者、书内数与“进入这本书”；句子有已审核Topic Tag时可点词→进入同名小径，先看到**这句**及“沿该主题继续”；点「在世界里看这句」等低权重出口→地图打开这句真点并指示它的位置，待访客再自主选其他点。标签未知时不显示“无主题”，也不加虚构的相似点入口。按“再来一句”才真正换当前句；前一句分享URL仍有稳定ID。

**边界**：现行`HallRoom`和`EncounterStage`没有“把当前句带入书房/小径/地图”的统一契约，阶段二先在本机样板实现并检验不破坏公平轮次与Back。若多一个地图出口挤走首屏主按钮，宁可从出处展开层接地图，也不强塞并列CTA；同数据对比两种位置，不增加任务。

## 2. 看世界：视觉模块不当第二个漫步器

**访客要做**：看到真实阅读痕迹形成的整体，识别**一点就是一条有出处的划线**，从地图主动挑一处读。世界总览仍可看密度/标签/一本书在图上的实际散布；标签中心、密度等高线与二维距离是布局/密度信息，不自动说明两句话观点接近。保持发布点位作第一版对照；新布局、分群和3D均留隔离试验，不是这一步完成交互的先决条件。

**状态与主动作**：

| 地图状态 | 访客看得见、能操作的内容 | 操作结果／返回 |
| --- | --- | --- |
| 世界总览，无句子 | 全图+清楚可见的书/审核主题入口，不画默认“相似”亮斑 | 点主题→该主题实际成员区域；选书→该书点亮；放大后点真点→读该句；无障碍列表可同样进入 |
| 来自一句或选中一点 | 该真实ID的点和完整原文在可对照的位置，已知来源可打开 | 关详情/Back→回原视框和焦点，不丢在图外；点别处是读者自行选择而非模型自动续读 |
| 点击句旁已审核Topic Tag | **由这个词发起**的同名Tag成员高亮，附文本“经审核同主题”，可进入真实成员全文 | 再点/关闭恢复底图；未知标签不把其余2,030条判作负例；同名不声称相似度值/一致观点 |
| 点亮一本书 | 该书真实点散布，书籍数和可打开的具体划线 | 回世界可解除筛选，进入书房须保留该书身份和返回原图 |

总览不能要求访客精确点中成千个细小点：先放大/区域/书籍筛选，再大触控目标或列表选择；既有世界/区域/详情机制可复用。访客首个动作应能直达可核查的真句，而不是先选阅读模式或读算法术语。若局部团进入样板，团可开真成员并显式说明其依据/漏出句子、保留全量访问；R4-L的书数量岛和无新增信息星座线不回来。桌面地图与全文相邻可核对；手机保留小而可见的定位参照，但不以黏顶遮住长句、返回和其他出口。文字列表/键盘必须完成等价任务，图层无需4,000多个DOM按钮。

## 3. 沿主题：范围明确的跨书阅读

**访客要做**：选择一个已审核Topic Tag，知道为什么当前句属于它；按「继续沿着〔主题〕走」才遇下一本书的相关句。现行56条小径/审核标签分配保留，书公平与全量可达先于embedding软节奏；不能把`draft`当已审核、不把共享Tag当观点一致。列表显示主题定义和真实书/句数量，不拿地图群名替代Tag证据。

**两种抵达**：从小径目录直接进某主题时可按当前规则抽初句；从某条**确有这个Tag**的划线点击时，样板应让该句先作为小径锚点，标题显示「正在沿着……」，再点一次才离开。这与目前首页TopicClues直接跳`/paths/:tagId`后随机起句的表现不同，是待验证的交互变化。标签岔路切换主题但保留当前句，下一步才按新主题走，Back恢复旧小径和进度；走完自然结束、由读者主动重开。已有`<details>`里的节奏切换不必在首次访客样板成为教学任务，暂不擅删正式控件。

**失败和退路**：标签失效/不在公开范围、只有一本/一条、重新打开页面、未知`?h`必须诚实说明且可退回；锚点首次加入轮次后仍保证每条合格内容可达、不重复，不因深链打乱按书公平。真实无Tag句不要被自动归进最近小径。

## 4. 主题书架与书房：从“再随机一次”变成“找书/读一本书”

**Book Theme书架**回答“这些书大体被放在哪类”；一本书可有多个Book Theme，**不**声明该书任一具体句子关于这个主题。当前`ThemeRoom`复用`StageRoom`，允许在书架内反复“再来一句”，这与首页主漫步的手势尤其相近。阶段二在隔离样板对照**书领路**的方案：点一个Book Theme→看这类真实书与少量来自这些书的真句作为可选线索→进入一本书；书架不以另一个显眼的无限换句按钮为主。不可用生成的“本类代表名言”，不可因减少按钮使这类书的句子丢失。

**书房**回答“这一本里我还想读什么”：保留当前有限轮次/去重/读完提示/主动重开及封面Aura，“再看一处”文案清楚其范围。若从首页/地图的该书句子抵达，优先让**同一句先出现**，然后再在这本书继续；从书籍目录直接进入则维持公平初句。必须决定锚点是否记入轮次、刷新如何恢复和Back回去何处；阶段二用一条真实短书/最长书的案例检验，不暗改原有轮次保证。书籍房间可主动点亮本书的地图点，Book Aura不被理解为Topic Tag颜色。

## 5. 分享、关于与跨页一致性：支撑真实阅读，不做主流程竞争者

分享只锁定当前高亮ID、原文、书名/作者与该句全部**已审核**Topic Tag；从任何房间弹出都不得把刚读的句子变成另一句。分享URL指向可直接阅读的原句，不依赖曾走的第几步。关于/技术页简洁交代微信读书是记录来源、本站对公开内容负责，skill是本机制作工具而非访客服务或平台背书（M-06待做）；不在图或首页堆技术解释。

页面之间使用同样的出处、Tag链接、分享和返回动作语言，但**不统一“随机下一句”的规则**。从首页/地图去书/小径要让当前句留在阅读现场，返回也能回到初来位置；新开标签/刷新无法恢复内存时，明确落到可分享的原句/房间，不能展示另一条却暗示仍是刚才那句。`/?h=`与`/map?h=`已经支持ID，`/books/:bookId`和`/paths/:tagId`当前**不含句子ID**；锚点如要跨刷新保留，需要在隔离样板设计可选地址参数或明确有限的同页session语义，不能在本稿宣称已实现。保留旧书/主题/地图/分享URL兼容。

## 阶段二要做的连贯交互证据

不先做独立体验审计。以真实可公开的短、中、长句各至少一例，包含无审核Tag、多Tag、同书/跨书、密集图点、单条书、无封面；让读者从**同一ID**依次试：首页读/继续→开出处→当前句进地图→地图点别处读/返回→当前句进书房读同书→回首页→沿明确标签进小径/转岔/返回。不是要求所有人按固定课程走，而是确保任一入口的交互语义一致、没有自动丢当前句。对照现有可用站点与隔离样板，明确每一项是真实已实现还是提案；1440/390/320+键盘/低动态与真实全文先过工程，Henry再分别判**功能/交互是否自然、得到什么信息、整站美感**。如锚点交接或地图/原文不能自明，先减功能或修交互，不加介绍层掩盖。
