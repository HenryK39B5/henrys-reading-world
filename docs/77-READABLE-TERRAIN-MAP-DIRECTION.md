# 77 — 世界地图新方向提议：从「点云＋主题入口」到「可阅读的地貌」

日期：2026-09-28。状态：**Henry已体验现有全站地图首版，认可手动漫游及局部真句/书信息，但指出仅知“附近有什么”还无法回答“所以呢”；本机新增读者主动选另一书、两真句/两真点对照，待Henry体验；未过信息价值/审美/独立访客Gate，未推送发布。** 不是隔离样板，不请Henry评价局部样本的想象手感；现有公开版本仍是基线。此前研究和授权边界见`docs/48/54/60–76`，执行证据见`docs/08`。

## 先承认原建议的问题

线上`/map`早已是一级导航，已具世界点云和地形、主题区域、亮书分布、**选中审核主题或书籍范围后**点真点、全文详情及返回；普通世界总览默认不能直接点所有3,462个点（`MapCanvas`的`interactivePoints`只含选中Tag/Book）。M-04隔离研究模式曾试过放大后在未筛选世界中直接点真点（见`docs/53`），**但未给无名局部空间可读的书和原文层**。首页、书房、主题小径也早已有下一句。`docs/74–76`说“地图能点真句、不会自动下一句”“保持书房/小径”大体是在**重述现状或做小修**；仅同句跨页、书架功能侧重点等是待实现细节。它们不足以回答“长时间研究地图后，这个模块到底变成什么”。不能把新增一个地图出口或已有点详情包装成地图重设计。

## 新命题：让空间直接露出书与原文

> **放大地图，不只是点变大，而是逐层看见这片地方真实有哪些书、有哪些划线；每一处文字仍留在它对应的真点旁。**

不是一张以主题目录为主要解码器的全点散布，也不是模型替读者选下一句。地图本身成为能被“走近并读出内容”的空间：世界看地形；走近任意一片（包括无名字的区域）就能看见这片二维范围内实际来自哪些书；选一句时正文与该点和附近位置可互相对照；关闭回到刚才这片地方。用户自己选下一处，不再给他另一套自动漫步。

这借鉴多尺度可视化的“随尺度切换可读内容”的方法，但**不是**宣称布局是真实语义地理。现有UMAP地形给二维导航与投影密度，图上共处不等于同一观点或自然主题。所有文字和书籍来自目前已批准公开的3,462条真划线；2,030条无审核Topic Tag依然参加地图和空间阅读，不因无标签被藏在背景。

## 三个尺度及一次完整动作

1. **世界尺度 — 有吸引力的全图**：保留已有深色地形视觉与全部真实点，不急着换算法。Topic Tag名称是已审核内容的局部路标，不是土地边界；不默认把当前句的“同标签”整图点亮。触点/拖动/缩放定位地图时，任何有内容的空间范围都可作为进入入口，不限56个已命名主题或先挑一本书。图面仍先作为作品成立，新增交互提示克制且能直接操作。
2. **片区尺度 — 这片真实含有什么**：选一片后保持整体方位，局部呈现该二维视口内的真实点与几本**确实有点位落在此处**的书；书名作为可操作的定位文字，展示有限个真实来源入口，其他内容通过片区列表/继续放大可达。列表/抽取规则可预计算且先按书去重/公平展示，不选择“最像主题”的假代表，不因单一本书划线多而统治首屏。若只有一本就如实只有一本；若是稀疏空区就不编内容。可报“这片图上有多少处划线、来自几本书”这类真实事实，但不写“这群句子表达同一问题”。相比线上当前**先从主题或亮书入手**的地域查看，以及M-04只改世界点命中的局部研究，这里任何无名地方也能显示可核实的书与文字，而非把“能点击点”当全部创新。
3. **阅读尺度 — 一点一篇完整原文**：点真实位置/书名入口，地图框架稳定，只有当前点与一段有书名作者的**完整划线**进入阅读焦点；附近原点仍能看到（手机需保留紧凑位置参照但不遮长文）。关闭全文回原片区和焦点，点另一个真点才换文。若当前句有已审核Topic Tag，读者从这个明确词主动触发已审核同名点显影；原位写明“同一审核标签”，不叫模型相似度，也不把其余未亮点称作没有主题。分享/进入书房/沿现有小径依旧绑定当前稳定ID。

图上少量真实书名在放大时才出现，全文只在读者选中一句时出现；不创建3,462个全文DOM或让几篇长文叠在地图上。桌面允许地图和文字对照，手机让地图的定位框和全文紧邻且保留返回，不复制研究页的黏顶图/长织锦/模型连线。键盘和语义片区/书籍/句子列表完成等价任务，不把Canvas指针当唯一入口。

## 与现版的实质差异，以及不做的事

| 目前已上线 | 此提案真正改变的地图任务 |
| --- | --- |
| 先看地形/Topic Tag或点亮一本书，再放大区域/点读详情 | **任意有点的无名片区也可打开**，地图按尺度逐渐显露当地真实书籍和句子，不靠预先知道标签/书籍名称 |
| 地图下方区域/书籍列表主要是目录和导航 | 书名与选中原文在地图的**实际位置与当前视框**形成一套可读内容层，读完原位返回、再自主挑下一处 |
| 当前渲染主语是点的数量/山形、标签 | 地图新增可核实的问题：“这里具体有什么书与真句？”；抽取/书籍覆盖/无标签区域也有明确处理，不生成思想总结 |

保留已有Book Aura与Tag小径（可从真实书/句进入），但**不**重画R4-L已经失败的书数量索引岛或无信息星座线；不把R4-K的模型前16自动续读带进地图；不强行把二维网格分箱说成天然语义团。主题透镜有价值但只在读者点击真标签后按需显影；已走织锦和双全文对读不作为首次访客必需层。图景可有地形的艺术性，但不能靠3D烟雾、假地名或算法结论给点制造关系。

## 核心风险与去留判断

**最大风险**：当前二维布局里的邻近不总能让相邻原文形成有趣对照；局部书名与句子可能像随机混杂。区域窗口是导航单元，**不是语义群或语义真值**。真实体验中如果访客看了多个地方依然得不到比随机翻书更多的发现感，不用增加文案、连线、动画救场：应回到地图关系模型或改成以书/已审核主题为主的其他图式；前期R2的近邻保留诊断和R4-A～F碎片/巨块/跨尺度失稳都是必须面对的反例，不宣称这个想法一定成功。

直接在现有完整站点上、用真实已审核公开全量数据实施后再由Henry看demo，而不是为漂亮片区挑有限案例。工程自验包括密集/稀疏、未知标签、单书占比高、多书交汇、最长原文、320/390px与键盘/返回/低动态；艺术感染力与信息价值分别看。若真要换生产点位/地形或引入3D，需在明确增加什么可读信息或理解后另作选择，并保持二维/文字完整退路。原公开网站与发布内容保持不变直到Henry另行授权。

## 2026-09-28 首版实做与未完成项

现有 `/map` 的公开数据消费者已接入**放大 / 点击世界任何无名位置 → 当地圆形读取范围 → 实际书目与一条完整原文 → 同位置真点详情 → 返回**。圆心和圆周画在Canvas，局部点用当前二维视图的屏幕几何做实时纳入和计数；书单按各书最近的真点排序，每书先露一处入口，避免按划线数量抢占首排。文案不宣称区域是语义群、审核Tag是相似度；无Tag的原文照样参与、可从分页文字目录开启。详细列表初始8处、按需再增16，**不是**一次把全体句子塞入DOM。桌面地图与文并列，手机地图上方紧邻原文；同一标签/选书/既有小径/分享未改。世界视框在本标签页刷新后可恢复；复位回世界也清除此记忆。研究专用 `map-study` 模式维持既有交互；公开快照、坐标、地形/算法未改。

首版与前述方向的距离须明确：没有新的缩放级别动态绘制书名标签；**书名目前在紧贴地图的局部阅读栏中**，只有一个真点被细环标出。尚未为已审核Tag增加单独主动显影的全图透镜，已有Tag/路径入口继续工作；也未声称此刻的局部搭配比随机翻书更有趣。1440图的一处窗口曾有171条/27本，390图的一处窗口有114条/18本；一本书可占几十条，书目去重防首屏霸占但不能消除二维混杂。需要Henry看**实际全站demo**后讨论信息价值与视觉冲击，再决定是否还需再向地图内部引入更细内容层或调整空间关系。独立首次访客、真机/Safari/读屏、真200%与低端性能仍未验证。完整本机执行和失败修复见`docs/08`；无需也未授权push/部署。

## 2026-09-28 Henry试玩后：由书名目录向自选真句对照迈一步

Henry实用后说地图手动漫游和局部书/句“很有意思”，信息增量似乎有用但有限：知道当前句与相邻书名，仍不知道为何继续。此反馈来自熟悉本站的本人，**不是首次访客或最终产品Gate**。问题不是缺更多数字，而是只有“附近有哪些书”尚未提供足以判断值得读下去的材料。Henry同意继续。

第二步已接入**同一现有`/map`**：每个局部圆保留一条当前真原文①；读者自己点选圈内另一真实书，才显示该书在**现有发布二维坐标**内最靠近①的一处②。地图固定，两个真实点以①②显影、不连接不证明相似；阅读栏把两篇完整原文及出处并列为前后有序的自选对读，点同一书可收起，点别的书可换第二句。只有真共享已审核Topic Tag时提供“共同分类线索”并明确非观点一致；没有共享词或任一句无Tag只说明同圈相遇，不制造负例。保留当前的全部原文目录、详细真点与分享、地图视框/Back/焦点；无新路线自动推荐、无模型服务、无真实数据/坐标/地形改动。首版按书去重列附近书仍在，但现在点书会先在当地读真句，而不是立即跳走。

**工程与真实视觉边界**：Chromium与Playwright WebKit各10/10、既有地图14/14、研究模式11/11、单测384/384、build/隔离通过，1440/390/320及720等效重排截图见`.private/review/map-readable/compare-*`。桌面可在固定地图旁对照两条原文，手机自然向下滚至②时地图离开视口，没有强加黏顶小图；在窄屏“图/文同时可见”的自然程度仍待Henry评判。截图中的纯地理近邻曾把两本小说的叙事句并排而无法给出清晰关联；这正是风险实例，不能因地图点真的、对读能打开就说信息已成立。只在原文确实让读者读出关联、分歧或奇异对照时，这项功能才比书名目录有意义；若大片地图仍只是随机拼贴，应回到点位/关系模型，不继续装饰。独立访客、真机Safari/iOS、读屏、真实浏览器200%及低端性能仍未验；推送部署需另行授权。

## 2026-09-28 第二次试玩后：先让人知道怎么进、怎么退

Henry已试玩上述两句对读，判断「还行」，要求继续完善想法，特别要求给访客清楚的进入与退出途径；这不是对任意近邻原文有意义的认可，也不是发布Gate。此次不借机新增自动推荐、评分或推翻已发布点位，而把**房间 → 真句 → 真点 → 当前地图 → 原房间**做成访客能自己走的环：

- 首页/主题书架的原句展开出处后，可按当前稳定ID「在地图看这句」；书房当前句有独立真点入口，原本「点亮这本书」的整书入口保留；小径当前句进入其同一Tag区域与原句。入口不是再开一个漫步器。
- 外部句子初次抵达地图时，若旧视框没有足够展示真点，摄像机仅在**抵达时**对准原点并放大；图内再选②或开/关详情、Back返回已能看到该点的视框时不重新飞行。总览补一句“点一处/放大一片”，局部阅读栏能显式回世界总览和来处；对读栏有「收起②」，详情有文字「返回地图」、来处和书/小径的各自出口。返回保留本次会话的书/小径/首页进度，刷新后的首页随机会话不承诺恢复没有稳定ID的原句。
- 视觉核对发现首版390px从外部句子抵达详情时只剩约97px地图露在屏幕上，真点几乎贴顶；将详情滚动落点向下移，现有截图可同时看到约190px地图含该点、原文和返回动作。滚到手机②长文时地图仍可能离开视口，不借黏顶小地图制造拥挤；两句仅因二维位置被一起阅读，审核Tag只作分类线索。

工程结果与先失败后修复记录见`docs/08`，截图`.private/review/map-readable/arrival-*`及`reading-*/compare-*`。用真实完整站点请Henry再按一条明确路径试用，并区分「能返回」与「读出值得继续的关联」两个问题；前者已工程验证，后者未过人体验收。公开快照、点位、地形、模型与线上版本不变，无push/部署。
