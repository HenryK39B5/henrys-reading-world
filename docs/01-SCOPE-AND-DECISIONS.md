# 01 — 范围与原型决策（v1 基线）

状态：供第一轮施工使用的默认方案，不是正式产品架构。Critique #1 后的最新目标与范围以 `docs/10-PRODUCT-DIRECTION-V2.md`、`docs/11-V2-IMPLEMENTATION-PLAN.md` 为准；本文件不冲突的技术克制与真实数据原则继续有效。

## 1. 本轮交付

本地可运行、可构建的静态单页 World：文字舞台 → 换句 → 原位出处 → 书籍 / 主题 / 年份探索 → About → 复制 / 稳定链接 / 分享卡预览。

用简单实现消除施工歧义。用户追加要求后，本轮允许使用移植的微信读书 skill 手动获取真实数据；这不是 Gate 3 的自动同步、正式导出架构或部署建设。

## 2. 已选默认值

| 决策 | 本轮选择 | 理由 / 可调整范围 |
| --- | --- | --- |
| 技术栈 | React + TypeScript + Vite，原生 CSS | 静态交互足够；不需要 SSR 或后端 |
| 状态管理 | React 本地状态 + 小型 reducer | 随机历史与转场可测，无全局 store |
| 导航 | `随便看看 / 主题书架 / 所有书 / 关于` | 入口明确，移动端也显示文字，不藏于 hover |
| 页面结构 | 六个房间，各自真实 URL | Critique #2 确认；单页长页已由 `docs/12 §2` 取代 |
| 深链 | `?h=<highlightId>`（房间内） | 静态服务无需 rewrite，刷新仍可定位 |
| 书籍详情 | `/books/:bookId` 独立房间 | 顶部出处层保持轻量 |
| 主题 | 3–5 个人工策展问题 / 短标题 | 不使用 AI 人格标签，不自动推断 |
| 近期 / 年份 | 同一探索区内的可选年份筛选 | 不另造时间线应用；缺时间则不猜测 |
| 分享卡 | 页面内可关闭预览，CSS 4:5 卡片 | 满足基础预览能力；PNG / 二维码暂不做 |
| 展示会话 | 当前页面生命周期，内存保存 | 刷新重新开始，不使用持久化追踪 |
| 书封 | 本地可公开图片，否则排版占位 | 不依赖外部封面 API，不抓取素材 |
| 字体 | 系统中文宋体 / 衬线舞台，系统无衬线 UI | 零外部字体请求；先验证可读性 |
| 数据 | 一个规范化、可校验的公开快照 | 更换内容不改组件；不做通用导入器 |
| 动画 | 淡出 160ms + 淡入 280ms | 440ms 总长；可在 Brief 范围内微调 |
| 用户持久化 | 无 | 不需要偏好存储或埋点 |

书封尺寸、字号断点、留白、主题卡数量等可小步优化，保留测试并记录。改变“首屏文字中心”“原位出处”“不发隐私数据”等原则必须升级 review。

## 3. 真实数据是开发前置条件

用户明确拒绝 fake data。取消任何演示内容替代方案：

- 产品页面、截图、录屏、分享卡与业务测试中的书摘，都必须来自 Henry 真实划线。
- 禁止用热门划线或他人的书摘冒充 Henry 的记录；禁止编造出处、年份、时长。
- 允许对已授权真实记录取子集检验单条 / 耗尽场景；缺失字段或空集合可用于结构边界测试，但不能变成页面假内容。
- 数据不足时如实减少展示或阻塞，不凑 30–50 条，不制造跨书跨年关系。
- 主题可以由 Agent 根据真实内容提出策展建议，用于本机开发并在私有审核表标为待复核，不写成 Henry 本人观点或人格判断；公开前确认，不阻塞本机施工。
- 用户已授权全部书籍的数据用于开发；直接读取真实划线并建立本机快照，不再等待逐书许可。

当前状态：接口与全量取数已完成；130 本有划线书籍约 4,700 行，去重后的候选池约 4,663 条。v1 快照使用其中 46 条；v2 将按 `docs/11` 让全量候选进入 local-only 产品。没有 6 本上限；正式发布前再确认公开清单，详见 `09-WEREAD-DATA-WORKFLOW.md`。

## 4. 本轮明确不实现

用户 / 权限系统、数据库、自动抓取 / 定时同步、后台策展 UI、在线学习、云函数、SSR、完整 SEO、远程 analytics、社交、Window、正式图像导出链路、公开部署。允许本轮按需手动调用只读 skill 获取已授权真实样本。

`pin / hide` 是数据准备期语义，不做用户操作界面。正式发布、版权复核、私有导出器、CI/CD 在 Gate 3–4 单独决定。

## 5. 模型工作边界与检查点

- 实现模型：选定范围内的代码、CSS、测试、已授权真实数据整理、局部体验修复。
- 高推理模型 / 用户：产品方向改变、原型体验批评、真实数据边界、Gate 2–4。
- Slice 1：先验证三档中文与转场，发现明显方向错误先修复。
- Slice 4：准备桌面 / 移动截图和 3–5 次换句录屏，建议提交 Product Critique #1。没有评审时可继续不改变方向的 Slice 5，不宣称 Gate 2 通过。
- Slice 5：交付工程结果与已知限制。真实访客反馈由人提供，Agent 不代填。

## 6. 范围控制

“功能可用”与“情绪价值成立”分别验收。若原型没有探索欲，应回到内容 / 首屏 / 顺序调整，不通过增加功能掩盖问题。所有未来能力只记录在 review 的后续项中，不趁本轮实现。
