# M-04: local interactive map candidate

Date: 2026-09-25. Status: local visual and interaction gate; the published map is unchanged.

## Open the candidate

1. Run `npm run map:terrain:study` to regenerate the ignored fixed-point density artifact from the approved public snapshot.
2. Run `npm run dev:map:study`, then visit `http://127.0.0.1:5176/map` (or the port shown by Vite). This is a loopback-only, public-snapshot study mode. Ordinary `npm run dev`, `npm run dev:local` and public builds retain the existing map. The study endpoint serves only the public-point-derived density, contours and bands; it refuses an artifact whose source version or points hash differs from the approved snapshot.

## Visual composition

The world and tag-region map use the unchanged 3,462 approved point coordinates and 56 topic labels, a precomputed 128 x 80 density grid, seven interpolated equal-density contours, small crosses at 1,000-coordinate intersections, WebGL2 continuous shading and **28% of the subdued isoband treatment** behind the existing Canvas points and labels. The raster density cells and continuous coordinate grid are absent in this mode. Color is a restrained intensity scale, not a tag classification or a statement of semantic certainty. When WebGL2 is absent, shader compilation fails or the context is lost, the local candidate switches to full-strength Canvas2D isobands; the published map does not acquire a WebGL dependency. Bands remain beneath dots and labels. The follow-up below adds point and contour hover to this local candidate; the published map remains unchanged.

## Original point-interaction candidate (superseded by the follow-up below)

- At world scale with no book or topic selected, tapping near a real point below the selection zoom animates a factor-1.8 zoom around the tap, capped at the existing 8x limit. The start thresholds are 3x for canvases at least 520px wide and 4x below 520px. Programmatic zoom lasts 210ms with ease-out; reduced motion skips the transition. Wheel, drag and pinch retain direct manipulation; a tap does not navigate while zooming. Topic-label clicks still win over points.
- Above the threshold, a point hit within 6 screen pixels opens the existing stable-ID detail immediately only if no other point lies within 8 pixels of it. If the tap is farther out (up to the 13px hit limit) or nearby points overlap, first tap shows a warm outline and a short excerpt in the existing map readout; tapping the same point again opens detail. Empty taps clear the pending selection. Pan/zoom clears it; book- and topic-filtered point selection remains as before. No new modal, DOM-per-point button or fabricated nearest-highlight description was added.
- Exact overlapping coordinates can still be impossible to distinguish by tapping. The existing topic, book and reading-list routes remain the honest alternate path; the study does not claim to make every point separately touchable. The density line is not a tag boundary or a click target.

## Follow-up: one-tap exploration and hover (2026-09-25)

Henry approved the terrain direction but found the two-step overlap confirmation inconsistent for first-time visitors. The world still zooms around a tapped dot below the existing 3x desktop / 4x narrow-screen threshold; **once at a selectable zoom, the first tap within 13 screen pixels opens the nearest real point even in a cluster**. Ties use the stable highlight ID. This deliberately treats the map as exploratory, not a precision selector. There is no preselection ring, second tap or additional panel; the existing detail, close behavior and accessible lists remain intact.

Mouse and pen hover add a soft warm glow and slightly brighter center to the nearest dot. This is not the sharp seven-pixel outline reserved for an opened passage. When the pointer is away from dots and labels but within four screen pixels of a contour, only that connected line lights in muted green; another hill at the same density level stays quiet. A contour remains non-clickable because it is an equal-density cue, not a named topic or destination. Drag, wheel, zoom and pointer leave clear hover; touch does not generate a persistent hover mark. Hover and tap share the 13px point hit radius so a lit contour cannot unexpectedly open a nearby point.

Unit coverage includes nearest/tied real points, connected contour grouping and pixel-space contour hit testing. Candidate Chromium now has 9 tests covering first-tap arrival, hover clearing, contour non-click behavior, touch and previous GPU/focus/reduced-motion paths. `npm run check:local` passed 315/315, `npm run build`, `npm run isolation:public` and `npm run publication:verify` passed; previous local map/label Chromium passed 15/15 on dedicated port 5188, public Chromium passed 8/8. Lettering is centered on the unchanged topic anchor; stable collision avoidance may still offset other names, while the invisible label bounds and 7px anchor hit remain available. Testing found a real contrast edge: the light current-topic name disappeared inside the lit `交易` point cluster, while uniformly dark lettering failed on the sparse `改革` region. No pixel readback, map-point suppression, artificial peak or semantic change is involved. A trial of `difference` compositing was rejected because lit-dot texture fragmented the glyphs. ## Accepted renderer integration (2026-09-25)

Henry selected the WebGL2 continuous shading plus subdued isobands approach. The accepted terrain renderer is now integrated into public builds and ordinary reading-map modes, while the original `map-study` endpoint remains available only for isolated study comparisons. Public builds load the fingerprinted static `src/data/public-map-terrain.json` asset generated from the approved 3,462 fixed public points. `dev:local` loads a separately generated `.private/local-map-terrain.json` derived from the 4,663-point local snapshot through the loopback-only `/__local_map_terrain` endpoint. Both artifacts carry the map version and points hash; build verification rejects a stale public artifact. The public bundle contains no `.private` data.

The accepted runtime uses WebGL2 continuous shading plus a 28% Canvas2D isoband layer. If WebGL2 is unavailable or initialization fails, the terrain canvas stays on the full Canvas2D band renderer; after a context loss, it remains on that fallback and continues to support resize, pan, zoom and route navigation. The point/label/detail Canvas remains above the terrain. No points, UMAP coordinates, public snapshot content or topic semantics were changed.

Evidence: public terrain artifact is 128 x 80 with seven levels and is about 117 KB uncompressed / 32 KB gzip in the build. Artifact unit tests pass 2/2. Public map Chromium passes WebGL and forced-no-WebGL fallback checks; ordinary local map/label regressions pass 15/15; Pages-style production preview map checks pass Chromium/WebKit at 1440/390/320px; isolated study interaction passes 14/14 plus one expected WebKit context-loss skip. `npm run check:local` passes 318/318, the full default local E2E passes 130/130 on its fixed 5173 contract, `npm run build`, `npm run isolation:public`, and `npm run publication:verify` pass. Remaining gate: Henry's explicit decision to publish/deploy. No push or deployment has occurred.

## WebKit, high-DPR and sustained interaction stability (2026-09-25)

Henry asked for the first M-04 follow-up while the previous loopback server was stopped. Confirmed `5176` was not listening; no service was restarted for the user. Added `e2e/map-study-stability.spec.ts` and a focused `npm run test:map:stability` command. The candidate now has a Chromium/WebKit stability matrix at device scale factor 2: viewport sequence 1440 -> 720 -> 390 -> 320 -> 1440, backing-buffer/CSS-size matching, no horizontal overflow, 24 alternating wheel and drag interactions, post-stress nonblank-map pixel checks (60 distinct samples in Chromium, 23 in WebKit), keyboard zoom and semantic topic-list navigation. The default Playwright suite excludes this dedicated study test. Chromium additionally loses WebGL context, verifies the Canvas band fallback, resizes to 390px and zooms again while staying on the fallback.

Results: the corrected stability run passed Chromium 2/2 and WebKit 1/1; WebKit's context-loss case is skipped because the extension is not consistently exposed there. A first run had two failures from an incorrect test assumption that a 720px viewport yields a 720px Canvas; the actual content width is 672px because of the page's 48px layout inset. The test was corrected to assert responsive shrink/grow and physical buffer matching, then passed. In the final isolated run, command-round-trip samples were Chromium median 780ms/max 912ms and WebKit median 247ms/max 388ms over 24 interactions; these include Playwright automation and are not frame-rate measurements. Screenshots and samples are in `.private/review/maintenance/m04/stability/`; `*-map-after-stress.png` captures the map before navigation and `*-after-navigation.png` confirms the list route. The Chromium fallback screenshot is nonblank and navigable.

This is desktop Chromium and Playwright WebKit evidence, not real iOS Safari, Android hardware, low-end GPU, long wall-clock sessions, or browser-menu zoom at 200%. The Windows environment cannot truthfully replace those device checks; the existing 200%-equivalent narrow viewport and keyboard paths remain automated coverage. The renderer deliberately stays on Canvas bands after context loss rather than attempting an unverified GPU recreation. No production map, public snapshot, coordinates or deployment changed.
