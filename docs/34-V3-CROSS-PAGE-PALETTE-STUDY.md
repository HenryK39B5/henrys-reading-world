## 1. 参考图带来的问题

用户同时提供了深色的 flomo 认知地图 / 微信读书书摘，以及以亮色为主的其他产品展示，不能从某一张参考图直接推论整个产品应采用单一深色。当前真正要验证的是：**同一张跨页构图，读者从真实点抵达一段真实文字时，哪一种明暗关系最有表现力，又不牺牲长读？**

这些参考图只在 `.private/reference/` 读取，未复制它们的图层、头像、二维码、山峰、统计或文案，也不把参考图作为产品资源。

## 3. 观察与取舍

| 相同状态 | C 全亮 | D 全深 | E 深图浅文 |
| --- | --- | --- | --- |
| 世界总览 | 与旧产品联系最自然，但真实点云在浅纸上缺乏重心 | 地图清楚，深绿空间气质鲜明；若整站照此铺满，仍可能像通用星图 | 真实地图成为明确的视觉主角，与另一页的阅读邀请形成差异 |
| 点亮密集书 | 书色与地图整体反差有限 | 书色可见，但地图上的色点需要更细的密度策略 | 与D用完全相同的暗图；暖纸阅读页为书色留出解释位置 |
| `h-013` 详情 | 原文可读，抵达感弱于E | 信息完整，但文字在第二块深灰面里，跨页关系主要靠边线维持 | 地图与纸面有清晰的材质切换，一次抵达在移动端也成立 |
| `h-231` 398字 / 320–390px | 连续阅读最自然 | 理论颜色对比高，但长篇暖色字在深底形成较密集的发光笔画；**视觉担忧，不是疲劳实验结论** | 兼顾地图的空间身份与长文的安静阅读；原文与3个标签均完整显示 |

推荐 **E 深图浅文** 继续：不是因为亮色一定比暗色易读，也不是因为参考图投票，而是它在**同一跨页关系里**让世界与原文拥有不同材质，同时保留中文长文的呼吸空间。D 全深可以作为严肃的备选，不应仅因为深色看起来“高级”而被批准；C 全亮稳定但缺乏用户要求的视觉跃迁。

### 定量边界

- 手机 390×844 同场景的地图 Canvas 顶部约 195px；320×720 约 233px。它们只是这套静态构图的数值，**不能**被当成产品界面验收结果。
- 三套的标题、引文和Canvas bounding box在各自对应场景完全相同。
- D与E在1440和390世界图里，对应地图画面裁剪后的像素字节完全一致（包括点、地名、图层），只有周围的页面材质不同。
- CSS指定的主要文字/表面对比（未包含系统字体抗锯齿）：C/E约13.49:1；D深灰阅读面约11.22:1。**高对比数字不证明长时阅读更舒服。**
- 所有PNG以固定真实样本截图；实测30/30文件、地图hash、点数和亮书数量都正确。

## 4. 诚实的不足

1. 三版共同的排版并非最终设计：320px 标题断成两行、工具仍是不可操作文字、密集书点的颗粒还需要专项打磨；配色选择不能掩盖这些问题。
2. C/D/E 的世界页固定展示 `h-013`，只是实验时锁住同一个真实样本，并在地图上标出对应点，**不能**成为产品默认策展策略。
3. 地图亮书示意色接近现有 `b-013` Book Aura；此静态脚本没有读取封面像素重新取色；正式产品仍须只从真实封面取色或统一fallback。
4. 未实测全站深色方案的门厅、书房、小径、目录、分享和完整键盘旅程；深图浅文的优先级来自地图跨页证据，不等于自动确定整个站点颜色。
5. 本研究未验证真实列表→详情的focus/scroll/Back、触摸、Safari、200%、reduced-motion、读屏或真实首次访客，也未执行产品回归。参考图不进入代码和public构建。
