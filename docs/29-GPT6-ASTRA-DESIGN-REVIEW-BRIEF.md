## 0. 最重要的委托

请把这次任务当作一次由资深产品设计负责人、艺术指导与交互设计负责人共同完成的 Design Critique。

**产品审美不是这个项目的表面抛光，而是核心产品能力。** Henry's Reading World 能否成立，很大程度取决于：真实文字、排版、留白、空间、Book Aura、主题小径和阅读地图是否共同形成一个有辨识度、愿意停留、愿意继续探索的阅读世界。

本轮最需要的不是泛泛评价，也不是“再加一点阴影 / 动效 / 渐变”，而是：

1. 判断当前设计是否已经形成独立、统一、可信的审美语言；
2. 指出哪些页面虽然功能正确，却仍像文档、原型或数据工具；
3. 给出可落到构图、排版、色彩、空间、控制形态和动效节奏的具体优化；
4. 建议一个明确的下一阶段视觉主方向和分批实施顺序；
5. 在提升作品感的同时，保护真实文字、长文本、移动端与无障碍。

请大胆批评。不要因为现有实现完整、测试很多而降低审美标准，也不要为了显得“更有设计感”而牺牲可读性和产品本意。

## 1. 产品是什么

一句话定义：

> 一个由真实微信读书划线、书籍房间、主题书架、思想小径和阅读世界地图组成的个人阅读空间。

希望访客得到的感受不是“看了一份读书数据”，而是：

> “我在一个人的阅读痕迹中漫游，并且好像稍微认识了他一点。”

核心空间语法：

| 数据 | 产品空间含义 |
| --- | --- |
| Book | 房间 |
| Book Theme | 主题书架 / 街区 |
| Highlight | 一处真实文字 |
| Topic Tag | 线索 |
| 同一标签下的划线 | 小径 |
| 多标签划线 | 岔路口 |
| 全量 embedding 布局 | 阅读世界地形 |

当前主要入口：

```text
随便看看 / 主题书架 / 主题小径 / 世界地图 / 所有书 / 关于
```

核心循环：

```text
遇见一句 → 再来一句 → 查看出处 → 进入一本书
                     ↘ 沿一条主题小径 → 在地图中观察世界
```

## 2. 不应被视觉审阅误改的产品边界

以下不是本轮希望重新讨论的内容：

- 只使用 Henry 的真实微信读书数据，不造 demo / fake 文本；
- 文字始终是房间体验的中心，地图是世界尺度的例外中心；
- 不做 Dashboard、阅读排行、打卡、社交、AI 问答、AI 搜索或人格总结；
- Book Theme 与 Highlight Topic Tag 是两套不同语义；
- 未可靠标注的划线保持无标签，不为覆盖率制造语义；
- Book Aura 来自真实书封，不为 Topic Tag 分配彩虹语义色；
- 不做通用 AI 渐变、玻璃拟态、卡片墙、标签云、节点蜘蛛网或仿旧纸张；
- 长文本不得裁剪，全部标签不得用 `+N` 截断；
- 键盘、屏幕阅读器、200% 缩放、移动端和 reduced-motion 是主路径；
- public snapshot 目前仍为空，本次不处理发布、部署或隐私出口。

这些边界不意味着现有视觉不能大改。导航、排版比例、页面构图、留白节奏、地图表现、控件语言、Book Aura 运用、移动端布局和分享卡片都可以提出系统性重构方案。

## 4. 当前视觉方向

已建立的关键词：

```text
Editorial / Spatial / Quiet / Tactile / Topographic / Luminous / Restrained
```

材料隐喻：

- **纸**：暖色底、留白、规则线、出版物节奏；
- **墨**：高可读正文与少量灰阶层级；
- **光**：Book Aura，让一本书以真实封面色影响环境；
- **地形**：全部划线共同形成地图密度、等高线、点和主题区域。

当前实现的明显倾向：

- 暖纸背景、宋体系正文、低饱和墨色；
- 很少使用卡片和阴影；
- 细线、大留白、轻量文字导航；
- 房间内容较克制，地图使用单一 Canvas；
- 分享卡片比消费者页面使用更深、更完整的出版色域。

这些原则可以保留、加强或被更好的系统替代，但请说明理由。

## 6. 请重点审阅的问题

### 6.1 整体艺术指导

- 当前是否拥有足够鲜明的产品身份，还是只是“做得很干净的阅读页面”？
- `纸、墨、光与地形` 是否真的形成统一系统，还是只在文档里成立？
- 页面之间是同一个世界的不同房间，还是一组使用相同 CSS 的独立页面？
- 克制是否已经变成过淡、过空、过于像 wireframe？
- 哪些视觉元素应该成为 Reading World 的独有签名？

### 6.2 文字舞台与房间

- 句子字号、行宽、行距、垂直位置和出处层级是否让人愿意停留？
- 桌面大留白是否有张力，还是显得内容不足？
- 移动端首屏节奏是否自然？导航是否抢占过多空间？
- 书籍房间中的封面、主题、正文和操作是否形成一个空间，而不是普通详情页？
- 长文本如何保持沉浸而不变成大段网页文章？

### 6.3 主题小径

- `/paths` 的长列表是否有阅读和探索节奏，还是接近设置列表 / 文档目录？
- 小径房间如何更明确地表达“我正在沿着一个概念跨书行走”？
- `纯公平 / 有呼吸`、进度、线索、出口等控制是否过于工具化？
- 岔路能否通过更精确的排版和空间反馈成立，而不是依赖解释文字？

### 6.4 世界地图

这是最需要具体建议的页面之一：

- 当前地图是否首先像一件视觉作品，其次才像工具？
- 点、网格、密度、等高线、标签与空白的层级是否合理？
- 地图轮廓是否太像技术散点图、单色热力图或调试产物？
- 标签白底、工具栏、缩放读数、书籍选择器和区域列表是否破坏沉浸？
- 如何增强纵深、尺度、地理感和“世界感”，但不做 3D、彩虹分类或花哨粒子？
- Book Aura 点亮一本书时，是否足够令人惊喜、足够像“这本书散落在世界中”？
- 移动端如何在首个有效视口中同时保住地图、方向和操作，不沦为缩小版桌面？
- 世界总览 → 主题区域 → 划线详情的视觉转场和空间连续性应如何加强？

### 6.5 色彩与 Book Aura

- Aura 在当前房间中过弱、合适还是缺乏结构？
- 色彩怎样影响纸面、规则线、局部光区和交互焦点，而不直接染正文？
- 是否需要比当前更明确的中性色系统和书籍色进入规则？
- 分享卡片的深色出版方向与浅色消费者世界是否属于同一个品牌？

### 6.6 导航、控件与细节语言

- 一级导航、页标题、返回出口和页尾链接是否形成清晰层级？
- 当前细线、pill、文字链接和原生控件是否使用过度或不一致？
- 哪些控件应该消失、降级、重组或换一种视觉形态？
- 动效应出现在哪里，持续多久，表达什么空间变化？
- 哪些细节会让页面从“完成的前端”提升为“经过艺术指导的产品”？

### 6.7 移动端

请不要只给“缩小字号、减少留白”这种建议。请单独判断：

- 移动端导航与首屏；
- 长划线；
- 小径进度与分支；
- 地图高度、标签密度、控制层和详情顺序；
- 分享卡片与对话框；
- 单手触控下的主次操作。

## 7. 期望的输出形式

请以“可以直接指导下一轮设计与实现”的精度输出，而不是只写审美感受。

### A. 总体判断

用 5–10 条结论回答：

- 当前设计最成功的部分；
- 最大的审美瓶颈；
- 是否已经形成品牌级视觉语言；
- 下一轮最应解决的核心问题。

### B. 保留 / 删除 / 重做

列出：

- 必须保留的设计资产；
- 应删掉或显著降级的元素；
- 需要系统性重做的部分。

### C. 视觉北极星

提出 2–3 个彼此有真实差异的视觉方向，不要只是换形容词。每个方向至少说明：

- 核心构图；
- 字体与排版关系；
- 色彩与 Aura；
- 地图语言；
- 控件语言；
- 优点、风险和适配度。

然后明确选择一个主方向，并说明为什么。

### D. 分页面具体建议

至少覆盖：

```text
门厅
书籍房间
主题书架 / 所有书
主题小径列表
小径房间 / 岔路
世界地图总览
主题区域 / 地图详情
分享卡片
移动端全局
```

建议使用表格：

| 页面 / 元素 | 当前问题 | 具体改法 | 预期效果 | 优先级 |
| --- | --- | --- | --- | --- |

“具体改法”应尽量写出可执行关系，例如字号级差、最大行宽、留白比例、对齐关系、色彩进入范围、控件重组、标签数量、动效时长或状态变化。不要只写“增强层级”“更有呼吸感”。

请引用具体页面、截图文件或 DOM 区域来支持判断。

### E. 地图专项方案

单独给出一套地图优化方案，说明：

1. 背景与纸面；
2. 地形 / 等高线 / 密度；
3. 点；
4. 标签；
5. 世界、区域、详情三个尺度；
6. Book Aura；
7. 控制层；
8. 桌面与移动端差异；
9. 转场与 reduced-motion；
10. 如何避免 GIS / BI 工具感。

### F. 分批实施建议

给出不超过 3 个设计实施批次：

- 每批解决什么；
- 涉及哪些页面与组件；
- 先做哪些静态方向稿或原型；
- 用哪些截图和交互作为 Gate；
- 哪些改动应避免同时进行，以免无法判断效果。

### G. 最终 Gate 标准

给出一份精炼的审美验收清单，帮助判断下一版是否真正变好，而不只是变得更复杂。

## 8. 审阅原则

- 先看真实页面，再看实现代码；不要从 CSS 写法反推设计价值。
- 可以挑战现有视觉方向和信息架构，但要区分“产品边界”与“当前表现方式”。
- 不要建议以功能堆叠解决审美问题。
- 不要使用竞品皮肤替代独立判断；可以引用设计规律，但不要要求复制某个产品。
- 不要把地图改成分析仪表盘，也不要把房间改成海报生成器。
- 不要因为项目重视克制，就容忍无张力、无身份或过于苍白。
- 每项高优先级建议都应能回答：它如何让访客更愿意读、停留、继续走，并感到这是一个真实个人阅读世界？
- 本轮先输出审阅与设计指导，**不要直接修改代码、数据或文档之外的实现**。
