# R4-A：Mapper 拓扑基线研究

日期：2026-09-26
状态：首轮基线完成；不替换线上地图，不接入产品。

## 研究问题

在不把一个主题压成单一中心的前提下，Mapper 是否能从真实划线中提供可读的群与连接？本轮只建立可复验基线，不把节点命名成主题真相，也不把边解释成因果或推荐关系。

## 固定输入

- 公开 `src/data/public-snapshot.json`：3,462 条划线、108 本书、56 个已审阅主题标签。
- 现有本机 `Xenova/bge-large-zh-v1.5` 1,024 维缓存；逐条 text hash 校验。
- 输入 snapshot SHA256：`ccef39e7410ba7dd1618a8038762933464dd35c45a98fb5f5fa48fb5e8c02c53a7c`。
- embedding cache SHA256：`49dbdbb49d2f660608bd4a3c0f2cc7c9eba8c430fb7fcdf9baceeec95514431e`。

## 基线定义

- Lens：对全部公开向量拟合 PCA，使用 PC1 或 PC2 的一维分数作为覆盖轴；分数只负责把数据分成有重叠的窗口。
- 每个窗口内部：在原始 1,024 维单位向量上按 cosine distance 建图；阈值内连通分量成为节点。
- 节点边：两个窗口节点共享至少一条真实划线时连接；边保存共享划线 ID。没有共享成员就没有边。
- 节点记录真实成员、书籍集合、已审阅 tag 集合和 lens 范围；不写入公开构建。
- 不使用标签训练聚类；标签只作为节点构成统计，未知/无标签不作为负例。

## 预登记参数网格

固定 `coverCount ∈ {8, 12, 16}`、`overlap ∈ {.25, .50}`、原空间 cosine distance threshold `∈ {.18, .24}`、`minSharedMembers=1`，分别运行 PC1 和 PC2，共 24 个配置。不按节点数量或视觉结果挑选参数。

## 实际结果

完整图写入 `.private/research/map/mapper-baseline/study.json`，摘要写入 `summary.json`。24 个配置的共同特征：

- 节点数约 `4,445–6,862`，远高于 3,462 个输入点；重叠窗口让同一点可进入多个节点。
- 平均节点大小约 `1.01–1.04`，中位节点大小为 `1`。
- 最大节点大小只有 `10–67`，取决于配置。
- 跨书节点占比最高约 `0.29%`，多数配置更低；大部分节点由单条划线或单本书主导。
- 边数约 `1,109–3,432`，但主要是窗口重叠产生的局部连接，不等于跨语义群连接。
- 覆盖率为全部 3,462 条划线；覆盖完整不代表群结构可读。

因此首轮没有发现可直接用于阅读探索的 Mapper 图。失败原因更具体地说是：当前“单轴 PCA lens + 原空间固定距离阈值”的组合，把数据切得过细；节点重叠主要连接同一划线在相邻窗口中的副本，而不是形成跨书、可审阅的语义群。

## 解释边界

本轮不能据此说 Mapper 无效。它只排除了一个具体基线：用 PC1/PC2 单轴覆盖、固定 cosine 阈值和连通分量作为聚类，不能直接得到适合访客阅读的拓扑摘要。后续更有价值的变化应优先考虑：

1. 更有信息量的 lens，例如局部密度、主题条件差异或高维距离函数，而不是只用 PCA 单轴；
2. 明确的局部聚类方法和最小节点规模，避免单点节点泛滥；
3. 把“共享窗口成员”与“共享语义成员”分开统计；
4. 对稳定节点和边做多尺度比较，再进行固定原文审阅；
5. 只把跨书且经过原文检查的结构作为潜在阅读入口。

不根据这轮结果修改公开地图，不启动产品观察器，不增加公开数据。没有远程请求、模型调用、真实数据取数或发布动作。
