> 日期：2026-09-18

## 1. 两种主题系统必须分开

### 1.1 Book Theme：主题书架

现有 14 个宽主题，属于 Book：

```ts
Book.themeIds: string[]
```

作用：

- 组织书籍街区；
- 主题房间从书架中的书公平抽句；
- 不声称具体划线语义属于该主题。

### 1.2 Topic Tag：划线线索

V3 新增，属于 Highlight：

```ts
Highlight.tagIds: string[]
```

作用：

- 描述一处划线涉及的概念；
- 形成跨书主题小径；
- 多标签划线形成岔路；
- 为地图山峰、山脊与山口提供人工策展语义。

Topic Tag 不是 Henry 的人格标签、立场声明、质量评分或公开推荐理由。

## 2. 标签内容原则

### 2.1 中等抽象度

优先命名可跨语境重复出现的概念：

```text
睡眠，而不是“睡觉”
运动，而不是“篮球”
希望，而不是“要保持乐观”
风险，而不是“期权希腊字母”
```

但不能机械要求语法上的名词。中文中的“等待、选择、行动、告别”虽然可作动词，也能作为稳定概念。判断标准是“可被命名、可定义、可跨书连接”，不是词性标注。

### 2.2 好标签的性质

1. **概念化**：名称描述概念、状态、机制或经验，不是具体动作指令。
2. **可延展**：能在不同书籍、体裁和语境中出现。
3. **可区分**：能说明与相邻标签的边界。
4. **文本可证**：完整划线本身能够合理支撑，不依赖臆测 Henry 或作者。
5. **可行走**：内容之间既有主线，也有差异，值得连续探索。
6. **中性**：不评价“智慧、正确、优秀、深刻”。
7. **简洁**：公开名称优先 2–4 个汉字。

### 2.3 避免

- 过宽：`人生 / 思想 / 社会 / 知识`；
- 过窄：只属于一项运动、一个人物、一个章节或一个专业名词；
- 带立场：`正确选择 / 优秀习惯 / 应该坚持`；
- 人格推断：`Henry 的乐观 / Henry 关注权力`；
- 复合捆绑：`希望与机会 / 自由与秩序`，优先拆为多个标签形成岔路；
- 书籍来源、体裁、作者名；这些已有 Book 与 Book Theme 表达。

## 3. 标签数量与地位

- 每条正式划线至少 1 个 Topic Tag；
- 通常 1–2 个；
- 最多 3 个；
- 所有标签地位平等，不设 primary / secondary；
- 标签显示顺序使用词表中的稳定 editorial order，不暗示第一个是主标签；
- 内容生产期允许 `needs-review`，但它不是可公开标签。

公开小径建议至少满足：

- 连接 3 本不同书；
- 至少 5 条划线；
- 有清晰定义；
- 不被单一本书垄断；
- 不宽泛到覆盖大部分语料。

阈值在真实标签分布出来后校准，不在 Batch 0 硬编码为 validator 错误。

## 4. 受控词表

私有词表建议：

```ts
type TopicTagDefinition = {
  id: string;                 // 稳定项目 ID，改名不换 ID
  title: string;
  definition: string;
  includes: string[];
  excludes: string[];
  aliases: string[];
  familyId?: string;          // 仅内部概念家族
  editorialOrder: number;
  status: 'draft' | 'reviewed' | 'publish';
  note?: string;              // 私有，不进 snapshot
};
```

公开词表保持扁平；`familyId` 只用于 Studio 中组织，例如：

```text
不确定的世界：随机性、风险、机会、概率
人的内在世界：希望、恐惧、欲望、孤独
行动与选择：决策、等待、行动、试错
组织与社会：权力、制度、激励、信息
```

概念家族不是公开小径，也不自动成为地图标签。

## 5. 内容生产流程

### 5.1 标签发现

1. 为全部 4,663 条生成私有 embedding；
2. 以书籍覆盖 + embedding 多样性抽取约 250–300 条；
3. 开放式归纳候选概念；
4. 合并同义、删除过宽 / 过细 / 无法跨书标签；
5. 建立约 30–60 个候选标签及定义；
6. 用户审核词表、边界与遗漏；
7. 选取每个标签的真实种子划线。

### 5.2 分批标注

每批约 200–300 条：

1. embedding 根据标签种子 / 中心提供候选；
2. 实现 Agent依据完整原文、标签定义和必要书籍上下文提出 1–3 个标签；
3. 保存 confidence、候选理由与模型版本到 `.private`；
4. 自动复核近义漂移、离群、漏标和同书机械标注；
5. 低信心与新标签建议进入人工 Gate；
6. 审核后才进入规范化 local snapshot。

不改写、截断或补全原文；不因为一本书属于某书架就给它的全部划线机械贴同一 Topic Tag。

## 6. embedding 边界

### 6.1 私有输入与缓存

建议目录：

```text
.private/embeddings/
  manifest.json
  highlights.json
  evaluation/
```

manifest 至少记录：

- provider / model / dimensions；
- 输入规范版本；
- local snapshot hash；
- 每条 text hash；
- 成功、失败与重试状态；
- 生成时间与成本摘要；
- 不记录 API key、账号标识或原始微信 ID。

API key 只来自非 `VITE_*` 环境变量。终端不打印向量、密钥或完整原文。

### 6.2 允许用途

- 多样性抽样；
- 标签种子与中心；
- 候选标签排序；
- 近义标签、离群和漏标检查；
- 地图高维语义位置；
- 小径候选中的语义距离控制。

### 6.3 禁止用途

- public 浏览器运行时调用外部模型；
- 单独提供“相似划线”入口；
- public / local AI 搜索或问答；
- 替用户自动批准标签或公开内容；
- 输出人格、立场、兴趣画像；
- 将 private-only 内容的向量或坐标混入 public snapshot。

## 7. 主题小径产品行为

### 7.1 小径列表 `/paths`

每条显示：

- 标签名称；
- 克制的定义 / 一句话说明；
- `N 本书 · M 处划线`；
- 进入小径；
- 切换到世界地图。

不做标签云、热门排行、彩虹色、词频字号或 Dashboard 卡片矩阵。

### 7.2 小径房间 `/paths/:tagId`

一次显示一条完整真实划线：

```text
正在沿着：希望

<划线>

——《书名》作者
线索  #希望  #等待

[继续沿着「希望」走] [分享]
```

显示有限轮进度，但文案可以比管理工具更自然：

```text
这一程已遇见 X / N 处
```

最后一条后不自动 reset：

```text
这条小径暂时走到这里了。
[重新走一遍] [看看其他小径]
```

### 7.3 岔路

当前标签在 UI 中标为“正在沿着”，其他标签是可转向出口。点击其他标签：

- URL / scope 切到新标签；
- 当前 highlight ID 不变；
- 轮次以新小径语义初始化或恢复；
- 下一次 `NEXT_PATH` 才从新小径离开；
- Back 返回旧路径及现场。

## 8. 小径算法：公平优先，embedding 调节呼吸

### 8.1 硬约束

1. 只使用拥有当前 tagId 的有效划线；
2. 先选书，再选句；
3. 多书时尽量排除当前书；
4. 书籍 cycle 公平，不按该书 tagged highlight 数量加权；
5. 本轮 highlight 不重复；
6. 全部候选最终可达；
7. 候选按 stable ID 排序，所有随机入口注入 RNG；
8. 空路径、单书、单条、耗尽与撤回稳定降级；
9. embedding 不得改变资格、公开范围或让某条永久不可达。

### 8.2 软节奏

选中书后，才在该书未见候选中依据与当前句的 embedding 距离选择。

目标不是每次最相似，而是“相关但有变化”：

- 避免最高相似度的近重复；
- 避免完全远离标签语义的离群点；
- 在近 / 中 / 远几个宽区间中随机切换；
- 节奏带随机性，不形成固定四幕或人格叙事；
- 无 embedding 或候选不足时均匀随机降级。

具体区间必须在 Batch 1/4 用真实向量确定。算法测试应证明：公平硬约束先于语义分数，固定输入 + RNG 可复现，embedding 关闭时全部性质仍成立。

### 8.3 public 运行形态

原始高维向量默认不进入 public snapshot。Batch 1 评测后在以下最小方案中选择：

- 导出经过量化的低维公开坐标；或
- 在导出阶段预计算小径需要的语义分桶 / 派生值。

选择标准：bundle 大小、确定性、可测试性、地图复用和不泄漏 private-only 内容。不得为了浏览算法在 public 运行时请求模型。

## 9. 世界地图

### 9.1 含义

- 每个点是一处真实划线；
- 点的高维关系来自 embedding；
- 标签为地形赋予人工策展名称；
- 相近标签可形成同一山脉中的相邻山峰；
- 多标签点自然成为山脊、山口和岔路；
- 标签分布过散可反向提示定义太宽，不强行把所有点拉成一个圆。

### 9.2 无核心标签的布局

不设置 primary tag。建议布局管线：

1. 对公开 / local 各自有效 highlights 使用同一模型向量；
2. 使用固定 seed 的降维算法得到初始二维坐标；
3. 每个标签的位置由其全部成员的稳健中心决定；
4. 标签只用于标注、轻量约束和质量检查，不硬改每个点的真实相对关系；
5. 多标签点同时参与多个标签中心，并自然落在重叠 / 过渡区域；
6. 生成密度场与等高线；
7. 版本化布局，模型、输入或参数变化必须显式重建。

若纯投影导致标签完全不可读，可在不伪造邻近关系的前提下加入可记录、可比较的轻量布局约束；不得手工拖点制造并不存在的主题关系。

### 9.3 三层交互

#### Level 1：世界总览 `/map`

- 绘制全部有效点作为地形纹理；
- 显示标签、山脉和等高线；
- 点击标签 / 区域，不要求每个点可点击；
- 可选择“点亮一本书”；
- 小径列表是完整替代入口。

#### Level 2：主题区域

- 放大当前标签；
- 当前标签点变清晰，其他区域降权；
- 相邻标签仍可见；
- 当前区域点才进入可交互集合；
- 多标签点显示岔路提示。

#### Level 3：划线详情

- 地图上展开完整划线卡片；
- 显示出处与全部标签；
- 可以进入书房、沿小径继续或关闭返回原地图位置；
- canonical 分享身份仍是 stable highlight ID。

### 9.4 点亮一本书

从书籍房间或地图选择一本书后：

- 该书所有点使用该书真实 Book Aura 点亮；
- 其他点降低对比度；
- 显示该书连接的标签与划线数量；
- 不画连接所有点的蜘蛛网；
- 无封面使用 `DEFAULT_ACCENT`。

### 9.5 渲染与可访问性

- 总览使用 Canvas、预计算图层或等效低 DOM 实现；
- 不创建 4,663 个 DOM 按钮，也不同时渲染 4,663 段文字；
- 区域层只暴露当前子集的可交互点；
- 移动端默认小径列表，地图主动打开为全屏 / 大画布体验；
- 键盘与屏幕阅读器通过小径列表、区域列表和当前划线详情完成等价任务；
- reduced-motion 取消平移 / 缩放动画，状态直接准确到位。

## 10. 分享全部标签

V3 卡片和纯文本都包含全部 tag：

```text
原文

#希望 #机会 #不确定性

——《书名》作者

来自 Henry's Reading World
```

要求：

- 原文逐字不变；
- 标签按稳定 editorial order；
- 卡片自然换行、自然增高；
- 不截断、不 `+N`、不横向滚动；
- tag 变更后 stable highlight URL 不变；
- public 落地页从当前 snapshot 解析 tag，不把 tag 名称编码进分享 URL。

## 11. V3 目标数据契约（草案）

当前 schema 2 不在 Batch 0 修改。目标 schema 3 至少需要：

```ts
type TopicTag = {
  id: string;
  title: string;
  description?: string;
};

type Highlight = {
  id: string;
  bookId: string;
  text: string;
  year?: number;
  tagIds: string[];
  pathVector?: number[]; // Batch 4：16 维量化软节奏投影，不是原始 embedding
};

type MapLayout = {
  version: string;
  points: Array<{ highlightId: string; x: number; y: number }>;
  labels: Array<{ tagId: string; x: number; y: number }>;
};

type SnapshotV3 = {
  schemaVersion: 3;
  visibility: 'public' | 'local-only';
  owner: Owner;
  themes: Theme[];       // Book Theme
  tags: TopicTag[];      // Highlight Topic Tag
  books: Book[];
  highlights: Highlight[];
  map?: MapLayout;
};
```

Batch 4 最终选择：只为 reviewed 小径试点导出 16 维、-127..127 整数的固定随机符号投影，用于选书后的近 / 中 / 远节奏；原始高维向量、confidence 与理由不进入 snapshot。地图仍将在 Batch 5 独立生成布局坐标，不能把 `pathVector` 当作地图点位。

## 12. 发布审核增量

原 publication policy 的书级 / 单条决定继续有效。V3 正式 export 还必须：

- 只导出 `status=publish` 的标签定义；
- 每个公开 highlight 的 tagIds 都指向公开标签；
- 排除 highlight 的 tag 与地图点完全消失；
- 排除书不会通过标签计数、地图点或布局元数据泄漏；
- public tag 数量、书籍覆盖、最长标签行和分享卡片经过审核；
- public 与 local 地图分别生成，不从 local 图层简单隐藏点。
