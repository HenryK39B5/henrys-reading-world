# R4-L — 固定视框的星座图与书岛图（本机图形语法对照）

日期：2026-09-27；**试验前契约**。Henry授权尝试其他“图”的样式，目标是更合理、更有趣，不求语义最优。此轮仅做同一句/同一条R4-K选路规则/同一固定视框下的三种画法：原发布坐标点云简图（非完整WebGL线上渲染）、星座图、书岛图；**并不比较三种语义布局算法**。在独立本机白名单观察器里实现，不改R4-K旧页、`src/`、`public/`或生产地图，不部署、push或调用远程模型。

## 冻结输入、图形语义与反例

- 沿用已审核公开3,462条/108本、现成`viewer-data.json`指纹`f95cfa8bb830a9e2600fceeb69a7101910c85906f452d207dde04431f99fca6d`、同一已发布二维点/轮廓及有向前16名单。起点预先固定为R4-K的11例，包括已知死路`h-043`、金融走廊`h-3501`、抽象漂移`h-2288`与长跳`h-4504`。所有版本仅按`routeNext.mjs`在读者主动按一次时续读，至多六步、可回退；不让访客每站选阅读模式，实验员可访问三条独立URL对照图形。完整原文/书名/ID可读，移动端地图与句子尽量共视，地图保持视框/点位在续读中稳定，不自动缩放/重排/追随当前点。
- **点云简图**：用已发布坐标及轮廓，点等于单条已审核划线、实线仅表示已走阅读顺序；此页不是完整生产WebGL地形复现。
- **星座图**：仍用已发布固定点位，但淡化轮廓、只在当前点绘制少量**原空间有向前16**候选连线，按真实rank取前若干且不显示三张预读卡；模型边不是关系真值、不是地形道路，阅读路线与候选线视觉区分。目的是检验节点/线的图形语法，不偷换点位、更不称其为新的更准地图。点击“下一句”的实际抽样规则不变；已知模型前几名未必包含自动目标，必须明确说明可视边只是当前几个邻居而非全部可选目标。
- **书岛图**：每本书一个独立岛，岛大小只随当前公开划线条数（直径为有界单调函数），所有书岛按公开书籍数量/ID的确定性网格位置排布；同书划线在岛内按稳定ID排位，路径跨岛只表示跨书的阅读顺序。这是**书籍索引**，岛与岛距离不表示语义，不能称主题岛。Book Theme和多重Topic Tag均不被迫唯一归岛；不因每本书含多主题而凭空生成“天然语义地区”。书岛布局一旦生成，单次阅读不动。
- 同图内的虚线只可表达原空间模型近邻；实线表达已走路径；书岛间连线同样不是两书的概念接近。主动选书与原世界地图逐点点击是现有产品重要能力，本机路线页不能声称替代此入口。浏览器报告保留`h-043`、`h-3501`、`h-4504`的原文/路线与长跳诊断，不据选出的漂亮路线宣称“惊喜”或估计准确率。

## 预先判败、证据和Gate

- 工程硬失败：三图切换方式改变相同起点的ID序列/书名/全文/模型rank；任何点ID/书ID伪造或重复、书岛漏点、标签被错当唯一归属；前进/回退/焦点让地图跳位或图框因为页面滚动消失；小屏/长段落遮挡全文/操作、键盘路线不可达、无文字替代、横向溢出/外部请求/白名单泄漏；没选后仍冒充存在候选；纯数字排序被文案误读为语义接近。每图固定像素及实际点位置、深路线后回退重走、死路、320/390/720/1440、reduced-motion须检验。候选只画少量可追溯的真实模型边，不做全点图边造成海量杂线；无动画时也能分辨当前点。
- 软失败：星座图路线/候选边杂乱或被误读为“故事因果”；书岛图108书在手机缩图拥挤、只有书籍身份而失去真正主题漫游；固定迷你图遮挡读段或压倒正文；所谓奇观靠刻意挑几步好看的句子。真实人对地图/阅读意愿的判断要等Henry反馈，Agent的原文直觉只算非独立记录。无法从孤立工程结果判断哪图最终更好；若两新图都输给现有图，也应保留失败而不是强推。
- 记录输入/实现指纹、命令、首跑失败与浏览器截图/几何到`.private/research/map/route-first/atlas-forms/`；完成后更新`docs/48`、`docs/54`、`docs/08`，小步本机提交。公开构建/隔离/parity不变是必要非充分条件；真机Safari/iOS、实际200%缩放、读屏、低端性能、未独立访客与权利继续开放；**正式地图/主题小径与部署另有Gate**。

## 执行结果（2026-09-27；工程观察，非访客/产品Gate）

在本机只读白名单服务新增`/atlas/published`、`/atlas/stars`、`/atlas/islands`三个**独立研究URL**，共用HTML/CSS、完整划线文字、单一主动“再读一句”与同一R4-K`routeNext.mjs`（指纹`e73cb42097e101ae4a056fde8ffda14c0ad8db8a711147787366db732a15ef3f`）。用户不需每站在图形/阅读模式之间做选择；三图是给研究者的对照入口。地图Canvas点位/视框保持稳定，手机地图作为粘顶小图、正文滚动，按步后只在新文字被遮挡或出屏时把文字标题滚回地图下方；此前R4-K页仍在`/next`，生产站点不变。桌面和手机实际地图是否稳住由浏览器位置测试核验，不能从`position:sticky`字样自行推断。

输入仍为已发布公开快照SHA256`ccef39e7410ba7dd1618a8038762933464dd35c45a98f5fa48fb5e8c02c53a7c`/冻结观察器JSON SHA256`f95cfa8bb830a9e2600fceeb69a7101910c85906f452d207dde04431f99fca6d`，无新WeRead取数、远程模型或高维向量浏览器交付。纯函数`atlasForms.mjs`：星图按当前真实候选顺序最多画4条有向跨书未读模型边；书岛按本快照每书公开划线数降序、项目书ID打破并列，排12列×9行，圆半径随该书划线数单调增长，圆内以稳定ID向日葵排位保存每条真实划线。108个岛、3,462个唯一点，无漏点、位置跨页/前进/回退保持不变；**这是一张数量排序的书籍索引，不是语义群岛。** 未给标签强行唯一归属。所有风格Canvas而非3,462 DOM按钮，完整原文/书名/路线文本是退路。没有额外依赖。

两次`node scripts/research/study-atlas-forms.ts`的报告逐字节一致（`metrics.json`SHA256`bc1687d9a6263aaa5be46bcbb701e89c5758fd22d9030ab41174c5d3687ac243`），记录实现指纹、11个固定种子的逐步ID与地图距离；10条各六步，`h-043`零跳死路，同样60条跨书边，与地图样式无关。发布坐标60边中位距离为对角线3.9%、最大49.4%；书岛索引60边中位24.3%、最大72.7%。**两张图的距离口径不等价，后者只是序号网格，不能用于“语义更差/更好”排名。** `h-3501`的金融题材走廊、`h-4504`的大幅跳转原文均原样保留；没有因为图好看就偷偷换下一句。

本机Chromium新对照14/14：三图×1440/720/390/320，固定真实原文/route ID与几何坐标、回退后重走、死路、六跳同路线、键盘Enter、reduced-motion、只读/Host/Origin/POST白名单、无外部请求/横向溢出。每个视口的`before/after`实际矩形和文字位置保存在`.private/research/map/route-first/atlas-forms/*-geometry.json`；1440×850一跳前后地图同为`(x57,y327,456×456)`，390×850同为`(x25,y11,150×150)`，新原文从屏幕y207开始；320×850同为`(x25,y11,132×132)`，新原文从y189开始。前/后和长跳27张浏览器图保存在同目录`screenshots/`。这证明这些自动化视口的滚动/点位稳定，不替代真200%缩放/真机触控/读屏。

初次新浏览器仅2/14通过：桌面新句不论是否可见都调用`scrollIntoView`，导致地图首次从y303/327滚到顶端，违反“屏幕里固定”的约定；现在仅在新文字被遮挡或离开视口时滚回文字，桌面地图不跳。其余移动用例因测试误把Playwright`boundingBox()`当有`bottom`字段而报错；改按`y+height`核对，同轮复跑14/14。失败日志保留`first-browser.log`，不是事后抹掉。离线脚本首轮数值写出但`tsc`因项目ES版本不支持`.toSorted()`失败，替换成拷贝后`.sort()`，typecheck/lint及再次数字复验均通过。这些是工程修正，不改变续读规则或冻结原文。

研究者非独立截图印象：星座图桌面点线把“当前位置→少量真实近邻→已走行程”分出了层次，但它**仍然使用已发布的坐标**，不是新语义投影，第一步默认目标rank13也不在仅画的前4条线中；极小手机图线和点难以区分。书岛把“从一本书到另一本书”的变化显得直接，书中划线多少也直观，但108座书岛在150/132px图上缩为数像素的小圆和明显的排序网格，缺主题邻近、易被误以为岛间远近有意义；目前**不宜宣称它是比现有地图更合适的世界总览**。移动端完整截图还有粘顶小图与正文间的内容/尾部留白代价。现有点云图仍是有意义的对照，未选赢家或据Agent个人观感声称访客惊喜。若下一轮要找更有世界感的新拓扑/图形，需要另立独立布局实验，不能从这个书索引平面偷渡出语义结论。

本机`npm run test`54文件377/377、typecheck/lint/build/isolation/publication parity通过；旧R4-J浏览器11/11回归，R4-K旧代码/旧页未修改。公开JS/CSS/terrain/snapshot构建指纹保持相同。Henry的实际比较、真机Safari/iOS、真实200%、读屏、低端性能和产品/发布选择仍未验证。没有写`src/`、`public/`、部署或push。

## Henry知情单人视觉反馈（2026-09-27；本轮两新图未通过）

Henry明确表示书岛图既不美观，也没传达有效信息；星座图看上去与旧地图相近，增加的模型关联线没有让访客理解新的内容或关系。他希望图像形式创新同时具有**有意义的信息价值与美学体验**，而非仅换一种图表或添线。完整原话在`.private/research/map/route-first/atlas-forms/henry-feedback-2026-09-27.md`。这是项目使用者直接反馈，**不能**把此前工程测试/Agent视觉印象写成审美Gate通过，更不能据此推断独立访客比例或宣称旧地图已是赢家。R4-L星座/书岛两种新增形式停止作为产品候选；已发布地图仍为有效对照，两个本机页与负例保留用于追溯，不据单条正面或负面意见覆写历史。

失败原因不是颜色、线宽或岛边缘没精修：书岛的按书数量/ID排序除了数量并不传达Henry关心的阅读关系；星座的原空间rank连线虽可追溯，但没展示为何这两句值得一起读，甚至默认下一句可能不在画出的四线里。下一轮不先选饼/柱/弦等形状；先写**信息契约**：某图在当前真划线与阅读动作里，读者比仅看原文多知道了什么、依据是标签交集（缺失=未知）/书籍身份/原文对照/模型排序中的哪一种、如何呈现疑点与反例、这种信息是否值得阅读空间。再用现有固定路线对照图文可读性、被误读的程度与视觉美感；不要用更花哨的视觉掩盖无价值连接。上述只是研究建议，没有开工新图、算法或正式发布。
