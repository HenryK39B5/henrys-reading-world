# 29A — GPT-6 Astra 无视觉能力时的文字化审美证据包

> 日期：2026-09-21
>
> 用途：当审阅模型不能读取图片、截图或 Canvas 像素时，与 `docs/29-GPT6-ASTRA-DESIGN-REVIEW-BRIEF.md` 配套使用。
>
> 当前代码基线：`bee0ad9`

## 0. 使用方式

没有视觉输入不等于把任务降级成代码审查。本文件把当前页面的视觉事实、截图观察、尺寸规则、色彩系统和主要构图转译为文字，使模型仍可完成一轮有依据的艺术指导与产品审美审阅。

推荐顺序：

1. 完整阅读 `docs/29-GPT6-ASTRA-DESIGN-REVIEW-BRIEF.md`；
2. 阅读本文件的页面叙述与视觉参数；
3. 阅读相关 CSS 和 React 结构，核对设计是如何被实现的；
4. 若具备浏览器但不能看图，可使用 DOM、computed style、文本层级和页面尺寸进行检查；
5. 按主任务书要求输出具体设计建议。

注意：下面的“观察”是对当前画面的文字转录，不是预设结论。审阅模型仍应独立判断哪些部分成功、哪些部分应该改变。

## 1. 全局视觉系统的可计算事实

### 1.1 Tokens

来自 `src/styles/global.css`：

| 角色 | 当前值 |
| --- | --- |
| Paper | `#f7f5ef` |
| Muted surface | `#eeece5` |
| Main ink | `#20231f` |
| Soft ink | `#60645d` |
| Faint ink | `#8a8d86` |
| Rule | `#d9d5ca` |
| Strong rule | `#bbb6a9` |
| Main accent | `#315f4b` 深灰绿 |
| Warm accent | `#8b4f3f` 暗砖红 |
| Stage font | `Songti SC / STSong / SimSun / serif` |
| UI font | 系统 UI / Microsoft YaHei / sans-serif |
| Main measure | `1160px` |

整体色彩非常克制：大多数页面由一层暖白、三层灰墨、细规则线组成。绿色主要用于 focus / hover / active underline；更明显的颜色通常只来自真实书封生成的 Book Aura。

### 1.2 页面框架

- 桌面主容器最大宽度 `1160px`，左右内边距 `24px`，顶部 `28px`，底部 `96px`。
- 移动端左右内边距 `20px`，顶部 `20px`，底部 `72px`。
- 桌面头部为品牌在左、六项文字导航在右。
- 移动端头部改为纵向：品牌一行，导航在下方自然换行。390px 下前五个入口占第一行，“关于”单独落在第二行。
- 品牌字号 `15px`；导航 `14px`；当前页仅使用墨色加细下划线区分。
- Local 状态使用一个 `13px`、细边线、全圆角的 pill：`仅本机 · 未公开审核`。
- 页面极少使用阴影、实色块和大型图形，主要依赖留白、字号和水平规则线。

### 1.3 正文舞台

来自 `src/features/encounter/stage.css`：

| 长度 | 桌面字号 / 行高 | 移动字号 |
| --- | --- | --- |
| 短句 | `44px / 1.7` | `32px` |
| 中句 | `35px / 1.8` | `27px` |
| 长句 | `27px / 1.9` | `23px` |

- 正文最大宽度约 `30em`，宋体，常规字重。
- 舞台最小高度桌面 `64svh`，移动 `66svh`，以 flex 垂直居中。
- 出处为 `14px` 灰墨，正文后 `20px`。
- 主动作通常是细边线圆角胶囊；分享是更弱的文字型控制。
- 换句只做 `160ms` 淡出、`280ms` 淡入，不做位移。

### 1.4 共同视觉语法

当前跨页面反复出现的形式：

- 暖白纸面；
- 宋体大标题和正文；
- 系统无衬线 UI；
- 极细横线；
- 灰色说明文字；
- 透明背景按钮；
- pill 形式的主操作或筛选；
- 页面底部一组纯文字出口；
- 最末尾折叠的“数据覆盖提示”。

这使页面具有一致性，但也意味着不同空间之间的视觉差异主要来自内容和少量布局变化，而不是更明确的空间构图或材料变化。

## 2. 页面逐项文字转录

- 画布为 1440×约 1100px，主内容宽 1112px，左右约 164px 空白。

## 4. 当前设计中可供审阅的结构性张力

以下不是既定结论，而是建议模型明确作出判断的矛盾：

1. **一致 vs. 同质**：暖纸、宋体、细线和长列表形成一致性，也可能让所有页面像同一份文档的章节。
2. **克制 vs. 苍白**：Aura 和 accent 很弱，保护了正文，也可能不足以形成品牌记忆。
3. **留白 vs. 未完成感**：门厅和 About 有很大空白，可能是沉静，也可能被理解为内容不足或原型状态。
4. **完整可达 vs. 目录疲劳**：56 条小径、130 本书和区域划线都需要可达，但重复行容易变成数据库列表。
5. **地图作品 vs. 技术可视化**：真实点、网格、密度和等高线有可信基础，但 toolbar、标签底板和单色散点可能带来分析工具感。
6. **空间隐喻 vs. 文案解释**：房间、小径、岔路和地图在产品语义上清楚，但部分空间变化主要靠“正在沿着”“继续走”等文字说明。
7. **浅色世界 vs. 深色分享卡**：分享卡片有强烈出版物完成度，消费者页面更轻、更空；需要判断它们是否属于同一品牌。
8. **移动完整性 vs. 首屏负担**：移动端保留完整导航、标题和控制，但地图或正文出现前需要经过较多界面元素。
9. **原生能力 vs. 艺术指导**：select、details、列表、按钮保持可访问性，但需要判断当前视觉包装是否足够精炼。
10. **真实内容变化 vs. 稳定构图**：句子可能从 18 字到近 400 字；设计不能只为最漂亮的一条样例成立。

## 5. 无图条件下仍可提出的具体建议类型

模型的建议仍应具体到以下层级：

- 字体系统：是否继续依赖系统宋体；标题、正文、标签、出处的字号比例和字重关系；
- 栅格系统：1160px 是否适合所有房间；正文、封面、地图和列表是否应共享或分化栅格；
- 垂直构图：首个有效视口中品牌、导航、标题、正文 / 地图的占比；
- 色彩进入规则：Aura 影响哪些表面、规则线、局部光区与状态，浓度大致如何分层；
- 列表节奏：是否分组、加入节奏节点、定义预览、改变密度或提供另一种入口；
- 地图层级：网格、等高线、点、标签底板、选区、当前点和控制的相对对比；
- 控件语法：哪些保留 pill，哪些改成文字、边缘工具、分段标记或更空间化的控制；
- 页面差异：门厅、书房、小径、地图如何成为同一世界中不同性质的空间；
- 动效：哪些变化需要淡入、位移、缩放、色温过渡，具体时长范围及 reduced-motion 降级；
- 移动端：哪些内容移位、折叠、后置或改为专注模式，而不是简单缩小桌面。

禁止仅输出：

```text
增强视觉层级
增加呼吸感
提升高级感
让地图更有沉浸感
统一设计语言
```

除非紧接着说明具体改什么、为何改、改到什么关系以及如何验收。

## 6. 无视觉能力时的审阅输出附加要求

除主任务书的 A–G 外，请在正式审阅中增加一节：

```text
## 证据限制与置信度
```

其中逐项区分：

- 可由 DOM / CSS / 文档直接确认的事实；
