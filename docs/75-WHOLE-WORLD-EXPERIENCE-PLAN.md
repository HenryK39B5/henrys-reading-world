# 75 — 全站阅读世界体验整合：下一阶段工作计划

日期：2026-09-27；2026-09-28 工作方式修订。状态：**Henry认可整体分工，优先各模块功能/交互；不做独立体验审计，也不做供他预先判断“手感”的隔离样本。先用文字共同确定核心设计，再直接在现有完整网站实现，最后基于真实可运行demo打磨。** 模块设计草案见`docs/76`。现行公开网站、真实内容与`7ebf2a3`地图点位仍是对照；R4研究与正式发布隔离。新地图算法/本机embedding可在研究中试，但不自动进入产品；远程provider与部署仍需单独许可。

## 决定要解决什么

不是继续逐篇问「还可试哪种地图形状」。把一个首次来访者看到的**整段体验**作为设计单位：从真实句子认识本站 → 愿意再读 → 看懂来源 → 主动去看整个世界/一本书/一个主题 → 打开一条真原文 → 原路返回，始终知道自己在哪里、为什么来到这里。首页无目的公平偶遇是主漫步；地图看整体并到达原文，不复制R4-K/M本机模型自动接句；主题/书籍的继续阅读有明确范围。一个有艺术感染力的跨页世界，不用把每页做成同一个黑色模板，也不能让好看的地形掩盖欠缺的阅读信息。

**确认范围**：Henry认可整体模块角色及文字设计→实际网站实现→demo迭代的工作方式；本文件提出的具体交互仍须通过这次文字讨论确认核心原则，不等于批准某个尚未见到的页面细节。现行`src/app/Nav.tsx`已有「世界地图」一级导航；首页改名、导航重组、分群/3D、地图生产坐标、引文/封面权利与推送部署均未被一并确认。Henry明确：不要先请他判断未接入实际网站的“样本手感”。

## 阶段一：模块功能与交互设计（非独立体验审计）

直接回答每个模块对访客**提供什么、第一眼能做什么、下一次点击发生什么、如何离开/返回**。现有页面/代码只做够用的定点核对以避免把已经上线的功能当新提案（例如六项导航已有地图入口），不产出大篇幅现状审计或泛泛的优缺点评分。具体交互契约见`docs/76-MODULE-INTERACTION-DESIGN.md`。

- 首页：真实划线/出处/按书公平「再来一句」是主动作；从**同一句**进入书、已审核主题或地图，未标注时仍能读与抵达地图，不增一个模型推荐步进器。
- 地图：定义总览、选书/区域、真点直达全文、关闭并复位、可选已审核主题透镜的逐次状态与显露顺序；保持已发布真实2D点位为初版基线，手机图文关系与无障碍文字替代作为同一交互的两种界面，不让访客先学模型术语。
- 主题小径：选一个已审核Topic Tag跨书读，当前主题、下一步、岔路、有限轮次和返回说清楚；书架/书房：按Book Theme找书、在一本书里看不同句子，不把书架分类错当逐句Topic Tag。
- 全站连接：分享链接与当前真句同ID；返回还原原地图/书/小径现场；从哪个模块去另一个模块是读者明确选择，不凭图距离/模型排名暗改算法。清晰列出现有行为、希望保留、待现有完整站点实现的变化；浏览器/程序只在阶段二实做时作为证据。
- 出口：用一份简明的、彼此能讨论的核心功能/交互构想确定主要行为与模块衔接；真实公开内容中2,030/3,462条无审核Tag是未知，多Tag/长文/小屏/无标签仍可达。不要把每个按钮都提前提交Henry做“手感Gate”；本稿确定核心后直接指导现有网站的实现。

## 阶段二：直接在现有完整网站中实现并运行demo

在文字确认核心设计之后，直接修改现有消费者页面/必要纯函数，使用**现有真实公开快照**在本机运行完整网站；不另建`/research`样板、不做只涵盖几个固定句子的平行页面。功能应在完整范围内可用，旧站与已发布地图仍作对照；线上发布保持原样。先实现最短跨页竖切并持续接入实际模块，阶段结果都在**同一真实站点本机demo**中体验，不把阶段结果拿给Henry逐个评“手感”。最少走通：

1. 首页真句与「再来一句」仍用按书公平旧规则；能不换句打开出处，主动进入地图或书房。
2. 地图/图文同屏或邻接：一处真点对应可读原文；选另一真点/区域可进入并返回原视框，不在地图添加第二个自动续读器。若从句子的已审核Topic Tag触发同标签点亮，文案/可见计数明确是审核分类证据，不是相似度；未标注时地图仍有入口而非制造负例。全量句子保持通过地图/书籍/替代文字路径可达。
3. 从真句进入同书更多文字或审核主题跨书小径，继续动作说清当前范围；返回原句/地图保留稳定ID与语境。主题书架仍按Book Theme，不能错当逐句Topic Tag。
4. 在首页、书房/小径和地图取**同一套完整视觉语言**与真实长短句，手机不能因小图、长文、固定控件让正文与返回远离。键盘与文字列表能完成同任务；低动态模式不失去方位。

记录实际输入/变更/失败案例，以全量真实数据运行，不为小样挑漂亮句；保留发布基线作回归对照。工程自验至少覆盖1440/390/320与720等价重排、无标签/密集区/长文/多Tag、Back/刷新/分享，必要时加入更多宽度和边界。**交付物是现有完整网站的可运行本机demo与完整跨页交互，不是另一套一次性样本。** 不因编译通过就自称访客/视觉Gate通过。

## 阶段三：基于真实完整demo打磨，再做独立验证

网站功能与跨页交互实际跑通后交Henry体验**实际demo**，让他指出具体问题并直接迭代；不预先请他评价纸面方案的“手感”，也不逐个局部样本设审美Gate。我们要在真实页面分别看能否自然继续阅读、是否看懂模块分工、图有没有新增可核查的信息以及跨页整体美感；Agent自己承担常规设计/实现取舍。达到有可体验产品后，再安排无讲解首次访客观察（理解点/原文/主题、能否返回）、真机与无障碍验证；Henry的熟悉反馈仍不冒充独立首访，邀请外部人员须另经Henry安排或明确授权。

**地图分支退出条件**：当前地图的真点→真句若足够直观且整站成立，可先收束产品，不让新算法阻塞。只有在实际站点使用时发现可验证的空间/阅读需求，再在独立研究中试有真实成员与稳定性依据的二维团或有明确收益的3D；不拿这些局部样本让Henry提前判断“手感”。R4-A～F单点海/巨块/尺度不稳及R4-L无价值连线/书岛均须保留为反例；新生产坐标/地形需另行产品与发布决策。
