# 75 — 全站阅读世界体验整合：下一阶段工作计划

日期：2026-09-27。状态：**Henry认可`docs/74`的整体角色分工，并将下一步优先级改为各模块功能/交互设计，而非独立全站体验审计；阶段一交互契约草案见`docs/76`，阶段二样板尚未实现。** 现行公开网站、真实内容与`7ebf2a3`地图点位仍是对照；R4研究继续与公开范围隔离。新地图算法、本机embedding可在隔离试验中研究；远程provider、正式快照/地图改动与发布仍需单独许可。

## 决定要解决什么

不是继续逐篇问「还可试哪种地图形状」。把一个首次来访者看到的**整段体验**作为设计单位：从真实句子认识本站 → 愿意再读 → 看懂来源 → 主动去看整个世界/一本书/一个主题 → 打开一条真原文 → 原路返回，始终知道自己在哪里、为什么来到这里。首页无目的公平偶遇是主漫步；地图看整体并到达原文，不复制R4-K/M本机模型自动接句；主题/书籍的继续阅读有明确范围。一个有艺术感染力的跨页世界，不用把每页做成同一个黑色模板，也不能让好看的地形掩盖欠缺的阅读信息。

**确认范围**：仅认可上述产品分工。现行`src/app/Nav.tsx`已有「世界地图」一级导航；`docs/74`提出的**名称/分组调整**、首页改名、默认地图形式、分群/3D、是否收起路径节奏选项、小径与书房是否要改交互、引文/封面权利与部署均未被一并确认。Henry进一步明确：**不用安排独立的“体验审计”作为重点，优先完成各模块功能设计和具体交互。**

## 阶段一：模块功能与交互设计（非独立体验审计）

直接回答每个模块对访客**提供什么、第一眼能做什么、下一次点击发生什么、如何离开/返回**。现有页面/代码只做够用的定点核对以避免把已经上线的功能当新提案（例如六项导航已有地图入口），不产出大篇幅现状审计或泛泛的优缺点评分。具体交互契约见`docs/76-MODULE-INTERACTION-DESIGN.md`。

- 首页：真实划线/出处/按书公平「再来一句」是主动作；从**同一句**进入书、已审核主题或地图，未标注时仍能读与抵达地图，不增一个模型推荐步进器。
- 地图：定义总览、选书/区域、真点直达全文、关闭并复位、可选已审核主题透镜的逐次状态与显露顺序；保持真实2D点位为样板对照，手机图文关系与无障碍文字替代作为同一交互的两种界面，不让访客先学模型术语。
- 主题小径：选一个已审核Topic Tag跨书读，当前主题、下一步、岔路、有限轮次和返回说清楚；书架/书房：按Book Theme找书、在一本书里看不同句子，不把书架分类错当逐句Topic Tag。
- 全站连接：分享链接与当前真句同ID；返回还原原地图/书/小径现场；从哪个模块去另一个模块是读者明确选择，不凭图距离/模型排名暗改算法。清晰列出现有行为、希望保留、拟在本机样板验证的变化；浏览器/程序只在阶段二实做时作为证据。
- 出口：同一套交互规则和真实边界样本（公开3,462句中2,030未标注为未知；多Tag/长文/小屏/无标注点都可达），可直接指导阶段二的**跨页联动本机样板**；不把阶段一做成看似完成产品的研究报告。

## 阶段二：一条从入口到地图、书、主题的**联动本机样板**

在独立本机路由或明确的隔离模式，用**同一批已审核公开真划线**和现有地图作为对照，做一个可实际点击的跨页切片，不是分别造四张漂亮静态稿。最少走通：

1. 首页真句与「再来一句」仍用按书公平旧规则；能不换句打开出处，主动进入地图或书房。
2. 地图/图文同屏或邻接：一处真点对应可读原文；选另一真点/区域可进入并返回原视框，不在地图添加第二个自动续读器。若从句子的已审核Topic Tag触发同标签点亮，文案/可见计数明确是审核分类证据，不是相似度；未标注时地图仍有入口而非制造负例。全量句子保持通过地图/书籍/替代文字路径可达。
3. 从真句进入同书更多文字或审核主题跨书小径，继续动作说清当前范围；返回原句/地图保留稳定ID与语境。主题书架仍按Book Theme，不能错当逐句Topic Tag。
4. 在首页、书房/小径和地图取**同一套完整视觉语言**与真实长短句，手机不能因小图、长文、固定控件让正文与返回远离。键盘与文字列表能完成同任务；低动态模式不失去方位。

冻结输入、ID、截图真实材料、布局/规则差异和失败反例；同时保留已发布地图和原页面作可点击对照。最少覆盖1440/390/320与一条720等价重排、无标签/密集区/长文/多Tag与Back/刷新/分享落地。工程检查说明可运行，不宣布视觉或首次访客成功。**交付物是一条完整访客旅程，而不是再多一个地图研究模式菜单。**

## 阶段三：整站产品/艺术Gate，然后才决定是否研究新群与3D

先由Henry体验联动样板，分别说：是否愿意继续读、是否看懂几个入口的差别、哪一刻学到可核查的真实信息、整站是否有他想要的视觉作品感。再准备无讲解的首次访客任务：用自己的话描述一点是什么、找到来源、在地图打开真句并返回、区别首页偶遇和沿主题跨书；观察者记录真实犹豫/误读，不能用Henry知情反馈替代外部首次访客。另验信息价值与审美，不用总分抵消严重误解。首次访客招募/邀请须Henry安排或另外明确授权，不擅自联系外部人员。

**地图分支退出条件**：现有地图的真点→真句足够直观且整站已成立，可先收束产品，不让全站等待新算法。只有观察显示“群”确实提供更容易理解/到达的新增信息，才在隔离条件下比较有真实成员、跨书与失败边界的二维团；3D仅在同动作和同原文下进一步提供清楚的空间收益或艺术价值且不误导时比较。保留R4-A～F单点海/巨块/尺度不稳及R4-L无信息连线/书岛的负例；不为必须产出3D而重复失败形式。若地图版本需要换生产坐标/地形，另行研究可复现性、标签支撑与空间方向感；任何一张美图不替代全量和困难案例。

## 阶段四：明确选择后才整合公开站点

若Henry批准具体样板/导航/地图改动，再把通过的最小变化接入现有页面，不创建第二个消费者应用；继续保留已确认的书、Tag与地图原文访问路径及旧深链/Back/分享稳定ID。完成跨页视觉、真实数据的全量/长尾、无标签、不重复/公平、书主题与逐句主题隔离、正式快照泄漏/构建一致性审计；手机/真实200%/reduced-motion/键盘/读屏/真机Safari/iOS/低端性能分别留证。M-06的微信读书记录来源与制作工具说明在关于/技术页准确收口，但不暗示平台背书或使用许可。公开内容和封面权利判断独立完成；发布/推送仍须另行明确授权，不能因产品Gate通过自动部署。
