## 证据与根因

- **实测真图失败先行**：在390px手机、地图4倍，当前点`centerX=5662, centerY=2407`，已审核`tag-006`「预测」文字锚点在画布内约`(217,112)`。仅横向拖动约27屏幕像素，到`centerX≈6012`后它仍在画布内约`(190,112)`，不是接近边缘；原实现却显示不出该字，鼠标底部读数改成底下的《黑天鹅》真点。`e2e/map-reading.spec.ts`新增此真数据失败用例，首跑Chromium **0/1**，原失败日志的断言是「应读预测、实际读《黑天鹅》的一处划线」。
- 第一原因是上轮在`visibleMapLabels(...)`**裁掉画布外名字之后**又按全图优先级`.slice(0,6)`（手机4倍，桌面12）。另一高优先级地名刚跨入视框，已在视框中央的「预测」从第六/第七位被挤掉。独立只读真实56个地名探针在390、320、桌面都找到同类内场反例；M-01的「世界预排后只裁边」不变量被破坏。
- 第二原因是每一个zoom值都重新按扩大中的字号、碰撞与候选名额贪心排一次，**并不保证已经出现的地名继续存在**。固定真实公开地名、按1→8倍、间隔0.05逐级审计，旧算法在390px的多个级别都使已入场Tag消失（例如`tag-051`约2倍），不是地名走出屏幕；不能只删`.slice`便宣称「缩放不闪」。初次只删视框截额，固定4倍拖动测试已从0/1转绿，但这项放大退场反例仍在，因此继续修根因。

## 修复契约

- **世界1倍不变**：复用原先纯真Tag排版的桌面18/手机10个已接受锚点和偏移。放大到4倍与8倍分别计算一次同一已审核词表的近景布局；已出现的世界名字不会被4倍布局反向淘汰。其余真Tag从2→4倍按固定全图排序**逐条取得单向入场比例**；更高倍的新名字从4→8倍进入。已出现的名字在继续放大时保留，世界名的偏移向近景位置**连续**过渡，不在某一比例集体跳位。既不按Tag多少调字体，也不声称相邻点同义。
- 在`MapCanvas.tsx`以真实数据、当前选中Tag、画布尺寸和地名字形缓存预排；**摄像机中心/当前zoom不参与重建**，拖动画面只做同一批标签的地图坐标投影与**几何边缘裁剪**。移除视框`slice`名额，Canvas测宽、描绘与命中使用同一排版；隔离研究`__MAP_STUDY_ENDPOINT__`保留旧画法。局部密度改由世界/4倍/8倍全图排版与碰撞处理，画面中最多几枚不再是假定恒等的6/12数字。用户选中区域仍保留原有Tag视框适配，不改房间阅读交互。
- 这不等于所有时刻都必须有字：**真的走出/走入画布边缘**时自然消隐/出现；逐字跨自己的预定入场缩放比例时出现，反向越过该比例则退出。无人给无名片贴大标题，不能把已审核Tag缺失当语义否定。
