# R4-B：局部 kNN 社区与 Mapper 多尺度基线

日期：2026-09-26
状态：首轮比较完成；不替换线上地图，不接入产品。

## 研究问题

R4-A 的固定距离连通分量产生大量单点节点。本轮测试一个明确不同的聚类基线：每个 lens 窗口内建立 mutual-kNN 图，再以连通社区形成节点；低于最小节点规模的社区被丢弃，并记录丢弃成员。目标是判断局部图能否在“单点碎片”和“巨型连通块”之间形成可读的中间尺度。

## 固定输入与规则

- 同 R4-A：公开 3,462 条真实划线、108 本书、56 个已审阅主题、1,024 维本机单位向量。
- Lens：全体向量拟合 PCA，固定使用 PC1 或 PC2 一维分数切窗口。
- 覆盖：`coverCount ∈ {8, 12}`，固定 `overlap=.50`。
- 窗口内图：每点取 `k ∈ {8, 16}` 个 cosine 近邻，只保留 mutual-kNN 边。
- 节点过滤：`minNodeSize ∈ {4, 8}`；低于该规模的社区不展示，但计入 `droppedPoints`。
- 节点边：只由相邻窗口共享真实划线产生；不解释成因果、推荐或语义真值。
- 共 16 个固定配置（PC1/PC2 × 2 covers × 2 k × 2 minimum size）。不按结果选配置。

## 结果

完整节点成员和边写入 `.private/research/map/mapper-local-clusters/study.json`，摘要写入 `summary.json`。

- `k=8` 时，节点数为 `10–34`，平均节点大小约 `176–573`；中位节点大小从 `4.5` 到 `726` 不等，说明不同 lens 会把数据切成完全不同的巨型社区。
- `k=16` 时，节点数为 `8–14`，平均节点大小约 `475–817`；多数配置已经把几乎全部划线合并进少数大块。
- 覆盖率约 `92%–99%`，但覆盖率提高伴随社区过度合并；仍有 `40–292` 条划线被最小规模过滤或未落入保留节点。
- 跨书节点比例大多在 `91%–100%`。这看起来像跨书结构，但节点规模已经大到难以作为可审阅语义群，不能把跨书比例单独当成质量指标。
- 边数约 `10–40`，主要反映窗口重叠下的大社区共享成员；不等于发现了 10–40 条清晰语义过渡。

这轮没有得到适合产品的中间尺度：R4-A 是大量单点碎片，R4-B mutual-kNN 则快速跳到少数巨型连通块。当前 PCA 单轴 lens 对社区形状的控制力不足，kNN 连通分量也不提供自然的节点边界。

## 阶段结论

排除第二个直接产品候选：**PCA 单轴覆盖 + 窗口内 mutual-kNN 连通社区 + 最小节点规模**。这不等于拓扑方法无效，而是说明需要改变“节点生成”本身，而不是继续微调 `k` 或最小规模。

下一步如果继续 R4，应优先研究：

1. 固定节点数量或密度的局部聚类，而不是连通分量；
2. 明确节点内部紧密度、最小规模和跨书构成的联合约束；
3. 以多尺度节点稳定性和真实原文审阅作为出口；
4. 将共享成员边与语义相似边分开，避免窗口重叠制造假桥；
5. 只保存少量可审阅候选，不为追求覆盖率保留巨型节点。
