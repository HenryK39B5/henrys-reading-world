## 用户提出的核心问题（不是已选方案）

Henry认为97几个文字方向有潜力，但希望再讨论具体交互模式，而不是只选择新颖排版。他提出：

1. 随机漫步：随机出现一句及相关几句，点击某句，再以它为核心呈现相关内容。
2. 文字湖泊：较疏、能看清真实文字的连续空间，用户在其中游泳/徜徉、观看湖或文字。

用户强调交互模式更核心。两者是供讨论的候选，不是要求马上做两套模式/给用户盲选。文字风场/绕排是表达与反馈，不是独立内容交互模式；Pretext即使可用也不替我们决定行动/内容接续。96仍废案，97技术核对不构成选型或新模式授权。

## 区分：一次动作改变什么

- 漫步的核心是**当前阅读中心与接续候选**变化，组织主要依靠实际访问序列。
- 湖泊的核心是**视野位置**变化；同一文字空间在点击前后持续存在，读者可以形成位置记忆。
- 若湖泊每次点击就随机重排，只是漫步的换皮；若漫步有漂亮字流但没有稳定中心/返回，也是效果演示，不是模式。

以一处真实划线为单位：可能一句，也可能多句/长段，不为了场景拼成新句。单元始终绑定原ID/全文/出处/全部Tag。运动与摆放仍不冒充语义距离。

## 1. 随机漫步的完整动作（Agent提案）

- 首屏：一处随机真实划线居阅读中心，周围少量（例如3–5处，非已确定参数）可读的继续候选。不是先散字再要求拼出句子。
- 周边文字可预览；点击作为“走到这一句”的明确动作：该句成为新中心，立即可读完整原文，旁边的接续候选随之更新。读取正文不等待动画，不把字体变形当新文本。可不再经过“先选中再点继续”两步。
- **这是区别于93–96选择/继续分开的新交互候选**；本轮不改现有路由/anchor合同。若选它，必须使“点周边=走一步”的对象角色明显，不能偷偷让普通阅读选择引发大范围洗牌/相机跃迁。
- 访问轨迹记实际ID，返回上一步恢复前中心及那时候选，而非重新抽取。另有明确“偶遇另一句”重新出发，不混入关联而不标明。
- 关联规则需真实且稳定：可用已有模型候选/真实共Tag等，但不能把无候选的空位用随机句补成假关系；邻居不是引用/赞同。这里尚未选规则/算法，也不声明语义最优。

优点：行动清楚、容易连续读与跨书、访问来路明确。风险：只成会动的关联推荐列表；每步全布局洗牌让人失去位置；读者一旦点了看过的句子无限绕圈。因此保留访问/回退，中心安定，周边变化有限，不以“更多点/更强效”当游戏收益。

## 2. 文字湖泊的完整动作（Agent提案）

- 首屏：一个持续存在、可移动视野的文字空间，当前可见部分有能辨认的真实字行/段落与留白。不是4,663段全文同时绘制，也不是随机字符/不可读纹理。湖是空间比喻，不强制水面、游泳角色或方向器。
- 拖动/滑动是在空间里逛，改变视野，不重新抽选整个世界。局部拨字/分流只是回应，不改变原文、成员或基准位置。
- 点击一段是在这里停驻阅读：该段就地清楚展开，周围让开，先前空间仍存在。展开改变局部排版而非永久挪走所有段落；收起/返回恢复之前视野，不丢位置记忆。长文允许正常阅读，不要求跟漂移字符追逐。
- 湖面不能长期自动流走导致“刚想看就没了”；主要由用户主动移动、可暂停局部。手机单击/拖动须区分，不用hover作为唯一入口。键盘与原生正文/目录仍有可达路径。
- 文字如何组成邻域尚未选：不能完全无规则随便撒，也不能把2D距离称确定思想相近。主题/来源/本机关系可作为组织候选，真正语义/艺术/可读性仍需检查，不在讨论中恢复新算法Gate或默认替换生产坐标。

优点：有主动发现、位置记忆与徜徉感，不局限一个锚点的候选列表。风险：漂亮但读不清的字海、初访不知看哪里、镜头比文字更重要、没有方向但不断拖。因而第一片应有少量清楚的阅读兴趣点，而不是靠全量密度制造规模；缩放/密度/世界尺寸尚未定，不让Henry凭空挑手感。

## Agent目前倾向：一个主流程，不做并列控制台

若偏“徜徉的阅读世界”，更倾向**湖泊为主空间，停驻后有可选的一步关联**：

1. 自由逛真实文字空间。
2. 点一处，停驻、就地阅读；湖面不换库、不洗牌。
3. 读者可选继续逛，或主动沿少量真实关联去另一处。
4. 选择关联才明确改变当前位置/中心，有可返回的实际来路；不把远处关系自动移进眼前伪装成原来就在附近。
5. 收起正文回到刚才视野；一条全局“偶遇”是另一个明确动作，不作为必需步骤。

这不是一屏塞两套按钮，而是“逛→停驻→决定下一步”。若优先非常清楚的连续阅读，独立漫步会更紧凑。上述倾向**不是用户已确认，也不是两套必做或新增状态机规格**。关联与湖的空间邻近不同：可以看起来相近却没有关系，也可以有真实候选关系却位置较远；表达需诚实。不能让新字体技术决定全部产品，再用动效掩盖这一差别。
