# 10 — Product Direction v2：轻松漫游，而非人设策展

> 状态：2026-09-12 用户确认的轻松漫游与公平算法方向。
>
> 历史权威：本文件记录 V2 的轻松漫游、公平抽样与 Book Theme 语义。**2026-09-18 起，`docs/19–22` 的 V3 方向优先：Book Theme 继续属于 Book，但 Highlight 新增人工策展的 Topic Tag；允许私有 embedding 辅助标签、地图和小径软节奏。** 本文件的非人格策展、按书公平、全量可达和真实材料原则继续有效。房间与 Book Aura 历史基线见 `docs/12`。

## 1. 方向修订

第一轮把核心目标写成“访客在 3–5 次偶遇后稍微认识 Henry”，并用 Opening / Contrast / Surprise、质量分和人工主题策展主动组织第一印象。用户在 Critique #1 明确指出：如果系统过度安排代表性、反差和回声，就会从真实展示滑向“人设打造”。

v2 不再把“形成某种 Henry 印象”作为算法 KPI，也不追求教育意义、留存或强吸引力。新的产品目标是：

> **把 Henry 真实留下的阅读划线放进一个可以随便抽一句、按主题书架或按书闲逛的个人阅读空间。**

访客可以自然形成印象，但那是浏览真实材料的副产品，不是系统预先编排的结论。

产品气质从“策展式偶遇”调整为：

- 轻松、真实、偶然、可闲逛；
- 有基本分布公平与防重复，但不编排叙事；
- 不保证每句都是金句、独立可读或有教育意义；
- 允许上下文不完整、意外、普通甚至略显奇怪的真实划线出现；
- 页面帮助材料被看见，不替材料安排寓意。

## 2. 继续有效的原则

- **句子仍是视觉中心。** 主题是当前浏览范围，不取代句子成为大型首屏菜单。
- 所有业务内容继续只来自 Henry 的真实划线；不使用 fake/demo 内容。
- 书名、作者、年份、封面与数量保持真实口径。
- 出处继续原位展开；书封与封面取色继续作为低权重视觉支持。
- 不做 AI 人格总结、传统社交、Dashboard、排行榜、阅读 KPI、打卡或推荐优化。
- 开发阶段可以使用全部真实内容；公开前逐条处理发布许可、政治敏感内容、版权和封面。
- `再来一句` 继续是核心动作，但它表示“继续闲逛”，不是进入被设计好的三幕叙事。

## 3. 明确停止的旧方向

以下机制不再作为 v2 产品要求：

- Opening / Contrast / Surprise / Exploration 四阶段；
- 为前 3～5 句设计代表性、领域反差或叙事节奏；
- `qualityScore`、`pinned`、`openingCandidate`、`surpriseCandidate` 参与随机概率；
- 用逐句人工主题标签描述“这句话在讨论什么”（**V2 历史停止项；V3 已由用户明确重新启用受控 Topic Tag，但仍禁止人格推断、质量评分和叙事编排**）；
- 把主题写成“Henry 反复关心的问题”或人格线索；
- 为保持首页漂亮而只让 30～50 条精选划线进入产品。

现有 v1 实现和测试保留为迁移前基线，不应边改边删除到无法对比；v2 切片完成后再移除无用字段和旧算法。

## 4. 主题的语义：书架，不是句子判断

主题标签属于 **Book**。一本书可有 1 个主标签和最多 2 个次标签；书中的划线在筛选时继承书籍标签，但 UI 不声称具体划线语义属于该主题。

推荐界面措辞：

- `主题书架`
- `正在逛：政治与制度`
- `从这个主题书架中的书随机抽取`
- `23 本书 · 862 处划线`

避免：

- `这句话属于政治与制度`
- `Henry 反复关注……`
- `从这些划线可以看出 Henry……`

标签应宽、平实、近似图书分类，例如：`概率与决策 / 交易与市场 / 政治与制度 / 历史与人物 / 小说 / 自我与成长 / 财富与商业 / 社会与关系 / 科技与未来 / 哲学与宗教`。这只是候选语言，最终词表必须从 130 本真实书籍及其划线归纳；避免“向内寻找”一类强解释、强人设命名。

### 4.1 书籍标注方法（V2 历史方法）

本节只描述 Book Theme 的既有一次性书籍分类：不引入 embedding、向量数据库或运行时模型，也不逐条标注 4,663 条划线。V3 的 Highlight Topic Tag 与私有 embedding 流程见 `docs/20`，不改写本节历史。

1. 从所有真实书籍生成本地 dossier：书名、作者、划线数量、若干覆盖长短和位置的真实划线样本。
2. Agent 先跨全库归纳 8～15 个受控宽标签，合并同义标签。
3. Agent 再为约 130 本书分配 1 个主标签、0～2 个次标签。
4. 结果写入私有静态审核文件；运行时只读取规范化快照，不调用模型。
5. 无法判断的书允许只用 `其他` 或暂不分配次标签；禁止为了满足主题数量编造精确语义。

标签是浏览工具，不是事实分类或出版评价。主题分类与逐条发布许可彼此独立。

## 5. 舞台模型

句子舞台保留，并增加持久的浏览 scope。

### 5.1 全部范围

- 默认显示 `随便看看`。
- `再来一句` 先公平选择书，再从该书选择一条划线。
- 不以划线总数直接加权，避免划线多的少数书支配舞台。

### 5.2 主题范围

- 用户从 `主题书架` 或舞台的 `换个主题` 进入。
- 舞台显示 `正在逛：<主题>`，并说明这是该主题书架中的书。
- 此后 `再来一句` 保持在该主题，直到用户主动换主题或回到 `随便看看`。
- 选择主题时应立即显示该范围内的一条真实划线并把视图带回舞台，不能只改变标签而保留范围外的旧句。

### 5.3 书籍范围

- 出处层的 `再看一处` 继续只在当前书内抽取。
- 它是临时书内动作，不改变持久舞台 scope；下一次全局 `再来一句` 仍回到当前的全部/主题范围。
- 单书详情提供 `随机看一处` 与分批的 `按顺序看`。

## 6. 公平发现算法

算法可以精心实现，但优化对象是**分布公平、少重复与可用性**，不是代表性或人设叙事。

全局或主题 `NEXT_STAGE`：

1. 根据 scope 找到有划线的候选书；主题 scope 通过 `book.themeIds` 过滤书。
2. 有多个候选书时排除当前书，避免相邻同书。
3. 优先本 scope 当前 cycle 尚未出现过的书；全部出现后开始新一轮。
4. 在同一优先级内均匀抽书，或按本 session 书籍曝光次数做简单反比权重；**不得按书中划线数量加权**。
5. 从选中书中优先抽取本 scope cycle 未出现过的划线；耗尽后重置该书/范围的划线 cycle。
6. 避免当前句和最近少量 ID；无法避免时稳定降级，不死循环。
7. 可仅为阅读节奏加入机械长度规则，例如连续长文时优先非长文；不使用意义、质量或“是否代表 Henry”评分。

算法必须接收可注入 RNG，保持纯函数、固定输入可复现。理由标签只用于测试：`all / theme / book / fallback`，不在 UI 解释算法。

## 7. 全量内容与页面密度

目标是让约 4,663 条真实划线全部**可到达**，而不是全部同时渲染。

| 层 | 可用范围 | 同时显示 |
| --- | ---: | ---: |
| 全局舞台 | 全部有效划线 | 1 条 |
| 主题舞台 | 该主题书架中的全部划线 | 1 条 |
| 主题首页 | 8～15 个主题 | 主题摘要、书数、划线数、少量封面 |
| 书籍首页 | 约 130 本书 | 默认少量，按需展开/筛选 |
| 单书阅读 | 该书全部划线 | 初始 8～12 条，之后每次追加约 20 条 |

“全部展示”的验收含义：每条有效划线必须能通过全局舞台、主题舞台或对应书籍路径被访问；不要求访问者在一次会话中看完，也不建立 4,663 行首页。

主题首页不再直接展开 10～12 条划线墙。点击主题的主要动作是进入主题舞台；可另有轻量书目预览，但不把全部句子堆在主题行下。

## 8. 信息架构与文案

推荐顺序：

1. 句子舞台（全部/主题 scope）；
2. 主题书架；
3. 书籍；
4. About。

年份筛选降为书籍区内部工具，只作用于书籍和单书列表，不过滤主题书架。当前只有 2024–2026，年份不是首页的主要探索入口。

About 只保留真实范围，例如 `这里收录了 4,663 处划线，来自 130 本书。` 不在访客页面解释“不做排行榜、不评价阅读者”等内部产品原则。

视觉仍保持文字中心，不增加首屏封面、主题大色块或封面墙；但允许按 `docs/12` 使用来自真实书封的低浓度环境色与轻盈房间动效。主题切换控件应轻，不与句子争夺视觉重量。

## 9. 产品成功标准

v2 不以“访客是否准确说出 Henry 的兴趣/人格”验收。更合适的信号是：

- 访客理解这是一个人的真实阅读划线，而非公共金句库；
- 能轻松地在 `随便看看 / 主题书架 / 一本书` 三种范围之间切换；
- 随机过程中不会明显被划线很多的书垄断；
- 所有真实有效内容都有可达路径，页面又不会同时成为文本瀑布；
- 访客觉得它像随手翻一个人的书房，而不是观看一场精心设计的人设展览。

真实访客仍可用于发现阻碍，但不要求产品强行提高点击次数或教育价值。

## 10. 暂不扩张（V2 历史边界）

> V3 已取代其中的 embedding / 逐句标签限制：允许私有离线 embedding 与受控逐条 Topic Tag；仍不做运行时 Agent、AI 搜索、问答或人格分析。

- 不做 embedding、向量搜索、逐句 AI 分类或运行时 Agent（V2 历史决定）。
- 不做用户画像、推荐学习、CTR 优化、访问埋点。
- 不做主题人格总结、序列叙事、每日一句、打卡或抽卡进度。
- 不做 130 本封面的首屏拼贴或 4,663 条无限滚动首页。
- 不做登录、评论、点赞、关注、多用户主页或自动同步。
- Slice 5 的分享与深链在 v2 数据和 scope 迁移稳定后继续，不抢先绑定即将废弃的 v1 状态结构。
